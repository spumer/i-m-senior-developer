# Проверка поведения плагинов Claude Code

Скилл ведёт работу с проверками плагинов: от выбора вида проверки до разбора
красного прогона и записи отчёта. Опирается на измеренные факты, а не на
предположения о поведении модели.

## Что выбрать: структура или поведение

Сначала определить вид проверки, иначе усилия уйдут не туда.

| Вопрос | Инструмент | Стоимость |
|---|---|---|
| Плагин загрузится, манифест и frontmatter валидны? | `claude plugin validate --strict` | бесплатно |
| Скилл срабатывает и ведёт работу правильно? | `claude plugin eval` | платно |
| Детерминированная функция даёт нужный результат? | обычный тест рядом с исходником | бесплатно |

Не писать eval для того, что проверяет обычный тест. Eval нужен только там, где
результат существует лишь в поведении модели.

Полный набор вызовов структурной проверки и её измеренные границы —
`references/validate.md`.

## Шаг 0. Предусловия

До любого платного прогона убедиться в двух вещах.

**Гейт раннего доступа открыт.** Проверять в пустом каталоге:

```bash
tmpdir=$(mktemp -d)
(cd "$tmpdir" && claude plugin eval)
```

`No eval cases found` — открыт, `currently in early access` — закрыт. Природа
гейта и его включение — `references/early-access.md`.

**Версия CLI закреплена.** Обновление меняет и формат результата, и поведение
модели. Порядок закрепления версии в непрерывной сборке —
`references/validate.md`.

## Шаг 1. Сформулировать наблюдаемый договор

Для каждого кейса ответить на четыре вопроса:

1. какой вход даёт человек;
2. какое поведение обязательно наступает;
3. что из этого наблюдаемо снаружи — вызов инструмента, файл, финальный ответ;
4. какая ошибочная реализация обязана уронить проверку.

Без конкретных ответов кейс не обоснован.

## Шаг 2. Собрать кейс

Кейс — каталог под `evals/` плагина: `prompt.md` с параметрами запуска и
`graders/*.md` с критериями. Формат, шесть типов критериев и их ловушки —
`references/graders.md`.

Предпочитать детерминированные критерии. Модель-судью брать только для смысла
ответа.

Проверить состав набора без расхода токенов:

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/skills/plugin-testing/scripts/check_eval_suite.py <plugin-dir>
```

Утилита обходит `<plugin-dir>/evals` и находит пять видов пустых проверок:

- кейс без критериев;
- неизвестный тип критерия;
- `max: 0` без `min: 0` — такая граница вызов не запрещает;
- запрет операторского инструмента, который кейс не запрашивает в
  `allowed_tools`;
- повторяющееся имя критерия внутри кейса.

Коды выхода: `0` — замечаний нет, `1` — есть замечания, `64` — ошибка вызова.

## Шаг 3. Обернуть прогон проверяющим скриптом

Прямой вызов `claude plugin eval` release-проверкой не считается: слишком много
способов получить зелёный цвет без доказательства. Вместо этого держать в плагине
`evals/run.py`.

Полный договор такого скрипта, обязательные проверки агрегата и способ проверить
сам скрипт подменным CLI — `references/wrapper.md`.

## Шаг 4. Прогнать и прочитать результат

Нулевой код выхода недостаточен: проверять агрегат результата по списку из
`references/wrapper.md`.

Красный прогон — находка, а не помеха. Ослабление порога, удаление критерия или
уменьшение числа повторов сохраняет зелёный цвет и уничтожает доказательную силу.
Порядок разбора по шагам — `references/failures.md`.

## Шаг 5. Записать отчёт

Отчёт описывает наблюдённый прогон, а не замысел проверки. Обязательные поля,
шаблон и правило отделения отчётов от общей документации —
`references/report.md`.

Пилотный запуск с одним повтором успехом не записывать.

## Три признака, по которым узнают знакомые тупики

**Кейс падает только на некоторых моделях.** Модель — значимое условие, а не
деталь: разбор в `references/failures.md`, шаг 3.

**Правки `description` дают неустойчивый результат.** Признак: один кейс
поднялся, другой остался на одном успехе из трёх. Лечение —
`references/deterministic-routing.md`.

**Повтор упал по таймауту или у судьи сетевая ошибка.** Это шум среды, не дефект
плагина: разбор в `references/failures.md`, шаг 5.

## Дополнительные материалы

### Справочники

- **`references/validate.md`** — структурная проверка, её измеренные границы,
  закрепление версии CLI в непрерывной сборке.
- **`references/graders.md`** — формат кейса, шесть типов критериев, ловушки.
- **`references/wrapper.md`** — договор скрипта прогона и его проверка.
- **`references/failures.md`** — разбор красного прогона по шагам.
- **`references/deterministic-routing.md`** — хук для устойчивого срабатывания.
- **`references/early-access.md`** — гейт раннего доступа и его включение.
- **`references/report.md`** — поля и шаблон отчёта.

### Скрипты

- **`scripts/check_eval_suite.py`** — проверка состава набора без расхода токенов.
- **`scripts/test_check_eval_suite.py`** — тесты утилиты; каждое замечание из
  списка выше закреплено отдельным случаем.
