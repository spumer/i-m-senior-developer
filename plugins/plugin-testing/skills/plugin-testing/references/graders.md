# Формат кейса и критерии

## Состав кейса

```text
evals/<case>/
├── prompt.md          # frontmatter с параметрами + тело как запрос человека
├── case.yaml          # необязательно: подготовка, replay, доп. каталоги
└── graders/
    └── <name>.md      # один файл — один критерий
```

Frontmatter `prompt.md` в Claude Code `2.1.234` допускает: `name`, `description`,
`tags`, `plugins`, `runs`, `expected_outcome`, `model`, `max_turns`,
`timeout_seconds`, `allowed_tools`, `append_system_prompt`, `env`. Незнакомый ключ
здесь отклоняется — в отличие от frontmatter команд плагина, где он проходит
даже со `--strict` (см. `validate.md`).

Значения по умолчанию той же версии: `runs: 3`, `max_turns: 10`,
`timeout_seconds: 300`.

Каталог со скиллом, но без манифеста плагина, автоматически плагином не
считается: указывать `plugins: ["../.."]` явно.

## Шесть типов критериев

### regex

Проверяет текст: финальный ответ, трассу или содержимое конкретного файла.
Поддерживает `match: contains | not_contains | count:N`. Встроенные флаги вида
`(?i)` не поддерживаются — использовать поле флагов.

Важно: цель `files` — список путей, а не содержимое. Для содержимого указывать
файл источником явно.

### tool_used

Считает вызовы инструмента, необязательно с проверкой аргументов регулярным
выражением.

Ловушка: `max: 0` без `min: 0` не работает, потому что `min` по умолчанию равен
`1`. Запрет вызова задаётся обеими границами.

### tool_order

Проверяет, что первый подходящий вызов одного инструмента произошёл раньше
первого вызова другого. Оба вызова обязаны присутствовать. Полный порядок всей
траектории критерий не задаёт.

### file_exists

Видит только файлы, созданные во время прогона. Файл, существовавший заранее,
подготовленный скриптом или лишь изменённый, критерий не заметит. Для таких
случаев проверять содержимое или сам вызов записи.

### llm

Передаёт выбранный результат модели-судье и проверяет по рубрике. В Claude Code
`2.1.234` судья запускается трижды и нужны минимум два голоса в пользу успеха;
голоса видны в результате прогона полем с голосами судьи. Для длинных файлов
судья менее устойчив: большие тексты лучше проверять детерминированно.

### baseline

Сравнивает новую траекторию с сохранённой. Это не то же самое, что сравнение с
запуском без плагина: первое сравнивает с эталоном, второе само запускает вторую
ветку.

## Правило доказательности

Критерий обязан различать работающую реализацию и сломанную. Два частых способа
получить пустую проверку:

**Запрет невозможного.** Проверка «не пишет файлы» ничего не доказывает, если
инструмент записи кейсу не выдан. Инструмент нужно выдать на двух уровнях: кейс
запрашивает его в `allowed_tools`, оператор разрешает флагом `--allow-tools`.
Только тогда отказ от записи становится наблюдаемым выбором.

**Поиск слов вместо смысла.** Регулярное выражение, совпадающее почти с любым
ответом, проходит и на бессмысленном тексте. Если проверяется смысл — брать
судью, а не расширять регулярку.

## Сравнение с запуском без плагина

Режим сравнения запускает две ветки и показывает разницу очков. Для кейсов, где
без плагина поведение принципиально невозможно, разница мерит наличие плагина, а
не качество поведения: такие кейсы прогонять без сравнения.

Критерий `tool_used` на инструменте `Skill` без явного указания ветки в режиме
сравнения автоматически становится индикатором наличия плагина и выпадает из
подсчёта очков.

## Многошаговое поведение

Живой вопрос человеку в headless-режиме недоступен. Поведение после нескольких
ходов проверяется воспроизведением записанного диалога: провести настоящий обмен,
сохранить транскрипт в каталоге кейса, указать его в `case.yaml`, следующий ход
человека передать запросом.

Транскрипт обязан быть записью состоявшегося прогона. Написанный от руки диалог
превращает кейс в проверку придуманного поведения.
