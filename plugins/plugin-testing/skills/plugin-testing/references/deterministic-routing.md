# Устойчивое срабатывание скилла

Описание скилла влияет на решение модели, но не задаёт его. Если поведение обязано
наступать всегда, нужен механизм, который не зависит от прочтения `description`.

## Когда переходить к механизму

Признак: после правок описания кейс проходит не во всех повторах. Измеренный
случай — один успех из трёх при неизменных смысловых критериях. Дальнейшее
переписывание описания меняет распределение, но не даёт гарантии.

## Хук UserPromptSubmit

Хук получает промпт до ответа модели и может добавить в контекст требование
вызвать скилл. Он не решает задачу скилла и ничего не пишет.

Подключение в манифесте плагина:

```json
{
  "hooks": "./hooks/hooks.json"
}
```

`hooks/hooks.json`:

```json
{
  "hooks": {
    "UserPromptSubmit": [
      { "hooks": [ { "type": "command",
        "command": "python3 ${CLAUDE_PLUGIN_ROOT}/hooks/product_intake_hint.py" } ] }
    ]
  }
}
```

## Требования к такому хуку

**Опознавать по явным признакам, без смыслового разбора.** Хук читает промпт
регулярными выражениями. Три независимых канала работают лучше одного:

1. явная команда плагина в промпте — сильнейший признак;
2. формулировка запроса («есть идея», «хотим»);
3. вопрос о начале работы («с чего начнём»).

**Иметь отрицательную границу.** Технические маркеры (баг, падает тест, рефактор,
готовая архитектура) подавляют слабые каналы, иначе хук перехватит обычную
инженерную работу. Явная команда плагина отрицательную границу не отменяет.

**Никогда не блокировать промпт.** Любой разбор входа завершается кодом `0`.
Битый payload — молчание, а не отказ.

**Быть на stdlib и без сети.** Хук выполняется на каждый промпт.

## Проверка хука обычными тестами

Хук — детерминированный код, поэтому он проверяется без расхода токенов. Нужны
две таблицы случаев:

- входы, которые обязаны срабатывать;
- входы, которые обязаны молчать.

Плюс отдельные проверки: технический маркер подавляет формулировку запроса; явная
команда плагина сильнее технического маркера; битый payload не блокирует промпт;
процесс всегда выходит с кодом `0`.

Такой набор ловит и ложное молчание, и перехват чужой работы.

## Чего хук не заменяет

Хук поднимает вероятность вызова, но кейс всё равно нужен: он подтверждает, что
связка «хук плюс скилл» действительно наблюдаема в поведении. Хук без кейса —
предположение, кейс без хука — неустойчивый результат.

## Порядок загрузки в песочнице

В песочницу eval попадает только проверяемый плагин, включая его собственные
хуки. Пользовательские хуки, память и другие плагины не загружаются. Поэтому хук,
добавленный в плагин, участвует в проверке, а локальные настройки разработчика —
нет.
