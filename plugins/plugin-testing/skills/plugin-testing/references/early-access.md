# Гейт раннего доступа

В Claude Code `2.1.234` команда `claude plugin eval` собрана и полностью
объявлена в справке, но запуск разрешается по организации. Публичной страницы
документации у команды на эту дату нет.

При закрытом гейте обе команды (`plugin eval` и `plugin eval init`) печатают одну
строку и выходят с кодом `1`:

```text
`plugin eval` is currently in early access
```

Это не сломанная и не отсутствующая команда: она намеренно закорочена на входе,
до разбора кейсов. Путь и фильтры при этом не читаются.

## Самопроверка

Проверять в пустом каталоге, а не в репозитории с кейсами:

```bash
tmpdir=$(mktemp -d)
(cd "$tmpdir" && claude plugin eval)
```

- `currently in early access` — разрешение до процесса не дошло;
- `No eval cases found` — гейт открыт.

Код выхода в обоих случаях `1`. Различать состояния только по тексту.

## Как открывается гейт

Разрешение включается на стороне организации и приходит клиенту вместе с
фича-флагами. Первичные клиенты подхватывают его автоматически после обновления и
новой сессии, без настроек.

Клиенты, которые серверные флаги получить не могут, используют переменную
включения. Это относится к развёртываниям через сторонних поставщиков, к трафику
через шлюз или свой базовый адрес, а также к клиентам с выключенной неосновной
телеметрией: там загрузка фича-флагов отключена целиком, поэтому разрешение
молча не приходит.

В CLI `2.1.234` проверка выглядит так:

```text
серверный флаг tengu_walnut_spire ИЛИ CLAUDE_CODE_WALNUT_SPIRE
```

## Куда класть переменную

Годится: окружение оболочки, задача непрерывной сборки, пользовательский
`~/.claude/settings.json` в блоке `env`, управляемые настройки.

Не годится: проектный `.claude/settings.json`. До подтверждения доверия к рабочей
области из проектных настроек применяется только белый список переменных, и этой
в нём нет — закоммиченное значение оставит команду закрытой.

Имя внутреннее и может измениться при обновлении CLI. После каждого обновления
повторять самопроверку.

## Диагностика закрытого гейта

Не создавать кейсы, чтобы «проверить» доступ: при закрытом гейте они не читаются.
Порядок: обновить CLI, начать новую сессию, проверить доступ организации,
проверить окружение процесса на переменные, отключающие загрузку флагов.
