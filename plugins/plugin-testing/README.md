# plugin-testing

Скилл для проверки поведения плагинов Claude Code: eval-кейсы и критерии,
обёртка прогона, разбор красного прогона, отчёт.

## Установка

```text
/plugin marketplace add spumer/i-m-senior-developer
/plugin install plugin-testing@i-m-senior-developer
```

## Откуда взято содержание

Скилл собран из разбора реального случая, а не из общих соображений. Проверка
плагина planner была красной: скилл продуктовой проработки не вызывался ни в
одном из шести повторов. Разбор дал три вывода, которые и стали ядром скилла:

1. модель — значимое условие прогона, а не деталь;
2. правки описания скилла дают неустойчивый результат;
3. устойчивое срабатывание требует структурного механизма — хука
   `UserPromptSubmit`.

После применения этих выводов проверка planner проходит три повтора из трёх при
строгом пороге. Отчёт — `docs/reports/planner.md`.

## Проверка самого плагина

Утилита `check_eval_suite.py` покрыта тестами рядом с исходником: девять случаев,
включая каждое замечание, которое утилита обязана находить.

```bash
python3 plugins/plugin-testing/skills/plugin-testing/scripts/test_check_eval_suite.py
```

Открытый пробел: у самого `plugin-testing` нет набора eval-кейсов, хотя скилл
требует их от других плагинов. Срабатывание его собственного скилла на
естественных формулировках поведенческой проверкой пока не подтверждено.
