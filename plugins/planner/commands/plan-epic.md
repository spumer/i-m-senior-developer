Активируй скилл `product-discovery` с видом документа `epic` и выполни его порядок работы от начала до конца. Для этого вида скилл загружает `references/epic-mode.md`.

Разбор `$ARGUMENTS`:

- Путь к замыслу с решённым исходом `epic` — гипотеза происходит из замысла: передай его в `sync` флагом `--parent`, чтобы помощник зафиксировал блок происхождения.
- Путь к существующей гипотезе (`EPIC.md` или её каталогу) — продолжение или пересмотр; сначала посмотри состояние через `inspect`.
- Достаточно сформированный свободный текст — допустим, только если уже называет проблему, ожидаемый результат и границу. Если границы нет — следуй правилам справочника, не выдумывай её.
- Пустой аргумент — уточни у человека, из какого материала строить гипотезу.

Значимые решения задавай через `AskUserQuestion` по протоколу скилла.

Успешный запуск всегда записывает результат в `epics/EPIC-NNNN-<slug>/EPIC.md`. После успешной записи в чате — только короткий итог по формату скилла: вид, путь и версия, два–четыре главных исхода, следующая команда, когда она есть. Следующую команду не выполняй сам. Если рядом лежит `ROADMAP.md`, итог отмечает результат его проверки свежести. Полный документ в чат не дублируется.

Метод, условные методы и проверка готовности — в скилле; не повторяй их здесь. При ошибке записи следуй разделу «Ошибка записи» скилла: подготовленное тело документа — запасной результат.
