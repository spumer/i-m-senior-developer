# Экспериментальный запуск

Запусти экспериментальный workflow-вариант выполнения плана для `$ARGUMENTS`.
Обычную команду `/planner:plan-do` этот режим не заменяет.

До успешной предварительной проверки не вызывай `Workflow`, агентов или другую
команду выполнения. При любом отказе не переключайся на `/planner:plan-do`.

Полная форма вызова во всех отказах по аргументу или пути:

```text
/planner:plan-do-workflow <каталог-фичи>
```

## 1. Проверь каталог и план

1. Если `$ARGUMENTS` пуст, сообщи, что экспериментальному режиму нужен каталог
   фичи, покажи полную форму вызова и закончи работу.
2. Считай весь `$ARGUMENTS` одним путём. Только read-only вызовом `python3`
   разверни `~`, разреши путь строго через `Path.resolve(strict=True)` и проверь:
   это существующий каталог, у процесса есть права чтения и прохода в него.
   Сохрани полученный канонический абсолютный путь как `feature_directory`.
   Если путь не существует, недоступен или является файлом либо другим узлом,
   назови исходный путь и причину, покажи полную форму вызова и закончи работу.
3. Внутри `feature_directory` проверь обычный читаемый файл
   `PLANNER_EXECUTION.md`. Его канонический абсолютный путь — `execution_path`.
   Если файла нет или он недоступен, не запускай workflow. Сообщи, что нужен
   текущий план выполнения, и укажи точную команду его построения:

   ```text
   /planner:plan <feature_directory>/ARCHITECTURE.md
   ```

4. Прочитай `execution_path` целиком. В YAML-заголовке найди непустое
   `architecture.path`. Разреши относительный путь от каталога
   `PLANNER_EXECUTION.md`, а абсолютный оставь абсолютным. Получившийся
   `architecture_path` обязан быть читаемым обычным файлом и не совпадать с
   `execution_path` после канонического разрешения. Иначе назови нарушенное
   условие, покажи полную форму вызова и закончи работу.
5. В текущем корне проекта проверь читаемый файл
   `.claude/planner-context.md`; его канонический абсолютный путь —
   `planner_context_path`. Отдельно через `CLAUDE_PLUGIN_ROOT` получи
   канонический абсолютный путь к
   `skills/planner/assets/plan_state.py`; это `helper_path`, и он должен быть
   читаемым обычным файлом. Если любой из этих файлов отсутствует или недоступен,
   назови его, покажи полную форму вызова и закончи работу.

Проверки пути выполняй инструментами до `Workflow`; не считай ошибку чтения
доказательством, что путь является каталогом или файлом.

## 2. Сформируй полный вход workflow

Прочитай раздел 1 файла `planner_context_path` и используй только его записи
каталога агентов. Не выбирай `general-purpose` как замену специализированной
роли и не используй имя, модель или скилл из другого источника.

Прочитай план выполнения и выдели его фазы реализации в записанном порядке.
Для каждой фазы подготовь объект:

```text
{
  key: <локальный уникальный ключ без идентификатора фичи>,
  title: <заголовок фазы>,
  implementer: {
    agent_type: <точное имя агента из раздела 1>,
    model: <модель, прямо названная в той же записи; Sonnet передаётся как "sonnet", Opus — как "opus", Haiku — как "haiku">,
    skills: <явный массив скиллов, названных в той же записи; если таких имён нет, []>
  },
  inputs: <дословно сохранённые входы фазы>,
  outputs: <дословно сохранённые выходы фазы>,
  review_scope: <дословная область ревью этой фазы>
}
```

Не добавляй неуказанные фазы, входы, выходы или область ревью. `inputs`,
`outputs` и `review_scope` должны присутствовать даже когда их значением
является пустой список, прямо зафиксированный планом. Ключ фазы служит только
локальной технической меткой и не содержит идентификатор фичи.

Подготовь также:

- `reviewer` — объект `agent_type`, `model`, `skills` для роли ревью из
  раздела 1;
- `documentation` — строку `not_required` только когда план прямо говорит,
  что документационная работа не нужна; иначе объект роли из раздела 1 с
  `agent_type`, `model`, `skills` и полным массивом `allowed_paths`, прямо
  разрешённых планом;
- `max_fix_rounds: 2`.

Вход workflow обязан содержать все поля:

```text
{
  feature_directory,
  execution_path,
  architecture_path,
  planner_context_path,
  helper_path,
  phases,
  reviewer,
  documentation,
  max_fix_rounds: 2
}
```

Не подставляй значение по умолчанию для отсутствующего поля. Пустой массив
`skills` допустим только как явное представление отсутствия скиллов в записи
выбранной роли; он не означает поиск или подключение скилла по догадке.

Если план не позволяет однозначно получить хотя бы одну фазу, обязательное
поле фазы, роль ревью, обязательную роль документации или разрешённые пути
документации, либо если соответствующей точной записи нет в разделе 1,
откажи до workflow. Назови недостающие данные, покажи полную форму вызова и
не выбирай другую роль.

## 3. Запусти ровно один workflow

После всех проверок сообщи, что запускается экспериментальный режим, и назови
`feature_directory` и `execution_path`. Затем один раз вызови только:

```text
Workflow({
  name: "planner:plan-do-workflow",
  args: <подготовленный полный объект>
})
```

Не вызывай другой workflow. Если этот workflow недоступен или его запуск
отклонён средой, сообщи точную ошибку и то, что экспериментальный запуск не
выполнен. Не запускай `/planner:plan-do` и не предлагай его как автоматическое
продолжение.

Верни результат workflow без полного текста отчётов. Для успешного или
остановленного запуска сохрани в ответе режим, состояние, число проверок
свежести, число рабочих вызовов, круги ревью, вмешательства человека и пути
отчётов из результата workflow.
