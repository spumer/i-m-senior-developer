# Roadmap — порядок срезов одной гипотезы

Справочник владеет телом документа порядка: горизонтами, условиями перехода и правилами движения элементов. Он не формулирует гипотезу и не описывает требования срезов — порядок упорядочивает уже сформированное и сам доказательств не создаёт.

## Когда загружается

Загружается, когда вид документа — `roadmap`: вход требует задать или изменить порядок срезов одной общей гипотезы. Проработка замысла, создание гипотезы и требования отдельного среза — другие режимные справочники, одновременно с этим они не загружаются.

## Расположение

```text
epics/EPIC-NNNN-<slug>/ROADMAP.md
```

Файл живёт в каталоге своей гипотезы, рядом с её `EPIC.md`. Свой номер порядок не получает: имя файла фиксировано, `allocate` для `roadmap` не вызывается. Идентификаторы существуют только у элементов тела.

## Когда нужен отдельный файл

Отдельный файл порядка оправдан, когда:

- порядок меняется независимо от гипотезы: гипотеза спокойна, порядок двигается;
- на элементы порядка ссылаются другие артефакты и устойчивые идентификаторы нужны вовне;
- порядок пересматривается по новым данным без переписывания гипотезы.

Если порядок — короткая одноразовая часть гипотезы, достаточно раздела «Возможные срезы» внутри неё. При сомнении порядок остаётся разделом гипотезы: отдельный файл появляется, когда его самостоятельная жизнь уже видна.

## Метаданные

Схема, которую помощник собирает при записи:

```yaml
---
plan_type: roadmap
version: 1
status: current
content_sha256: <отпечаток тела>
state: active
epic:
  path: "./EPIC.md"
  version: 2
  content_sha256: <отпечаток тела EPIC>
---
```

- `state` — состояние порядка работ. Закрытые значения:

```text
active | paused | completed | cancelled
```

- блок `epic` обязателен: ссылка на гипотезу в том же каталоге с её версией и отпечатком. Один порядок принадлежит одной гипотезе.

Тело готовится без метаданных: их пишет только помощник по флагам `--state` и `--parent`.

## Тело документа

Шаблон:

```markdown
# ROADMAP — EPIC-0007

## Now
| ID | Срез | Условие завершения | FEAT |
|---|---|---|---|
| RM-01 | ... | ... | features/FEAT-0021-... |

## Next
| ID | Срез | Что должно произойти раньше |
|---|---|---|

## Later
| ID | Срез | Почему не сейчас |
|---|---|---|

## Основание порядка
...

## Сейчас не делаем
| Что | Почему | Условие возврата |
|---|---|---|
```

Заголовок называет гипотезу своего каталога.

Идентификаторы элементов — вида `RM-01`, `RM-02` и далее. Они присваиваются при появлении элемента и не перенумеровываются при перестановке: на элементы ссылаются другие артефакты. Номер убранного элемента повторно не используется.

Колонка условия перехода обязательна в каждом горизонте:

| Горизонт | Колонка | Что фиксирует |
|---|---|---|
| `Now` | Условие завершения | наблюдаемый признак, по которому элемент покидает ближайший горизонт |
| `Next` | Что должно произойти раньше | событие, открывающее элементу переход в `Now` |
| `Later` | Почему не сейчас | причина, по которой элемент сейчас не рассматривается |

Четвёртая колонка `Now` — ссылка на каталог среза. Она есть только в ближайшем горизонте: остальные горизонты держат кандидатов, для которых срез ещё не создан.

«Основание порядка» объясняет текущую последовательность: какие зависимости и сведения её определяют. Каждое изменение порядка обновляет основание.

«Сейчас не делаем» собирает убранное из горизонтов: что, почему и при каком условии элемент возвращается.

## Жёсткие правила

1. Элемент попадает в ближайший горизонт `Now` только когда для него уже создан срез с готовностью `ready`. Кандидат без готового среза остаётся в `Next` или `Later`.
2. Дат нет. Условие перехода — событие или наблюдаемый признак, но не срок.
3. Порядок меняет только эта команда. Рефлексия после задачи, внешний и встроенный поставщики порядок не переставляют: предложить изменение могут, записать — нет.
4. Сырой замысел не создаёт порядок срезов напрямую: сначала нужна сформированная гипотеза с кандидатами срезов. Вход без неё уходит в проработку замысла или гипотезы.
5. Один порядок принадлежит одной гипотезе. Порядок нескольких гипотез (портфельный) в этот выпуск не входит.

## Работа после доказательств

Доказательства приходят снаружи: поставленный срез, проверка гипотезы, новые данные. Сам порядок доказательств не создаёт. Каждый шаг записывается с основанием:

| Шаг | Что происходит | Основание |
|---|---|---|
| Продвижение | элемент переходит в `Now` из `Next` или `Later` | условие перехода выполнено, срез готов |
| Перестановка | элемент меняет место внутри или между горизонтами | новые данные или изменившаяся зависимость |
| Приостановка | порядок переводится в `state: paused` | потерян аппетит или ресурс, открылась блокирующая зависимость |
| Отмена | порядок переводится в `state: cancelled` | опровержение гипотезы или исчезновение результата |

Основание попадает в «Основание порядка». Элемент, убранный из горизонтов, — в «Сейчас не делаем» с причиной и условием возврата. Приостановленный порядок сохраняет тело целиком; возврат в `active` записывается с основанием. Завершение (`completed`) — ближайший горизонт исчерпан и продолжение не планируется.

## Запись

Проверка цели идёт с родителем — гипотеза обязана лежать в том же каталоге:

```text
python3 "${CLAUDE_PLUGIN_ROOT}/skills/product-discovery/assets/product_state.py" \
  validate-target roadmap <path> --directory <dir> --parent <EPIC.md-path>
```

Тело пишется во временный `ROADMAP.md.prepared` рядом с целью, затем синхронизируется:

```text
python3 "${CLAUDE_PLUGIN_ROOT}/skills/product-discovery/assets/product_state.py" \
  sync roadmap <path> --body-file <path>.prepared --semantic-change <yes|no> \
  --state <active|paused|completed|cancelled> --parent <EPIC.md-path>
```

`--state` и `--parent` передаются при каждой записи. Смысловое изменение — `yes` при любом движении элементов, смене состояния или основания; правка формулировок без изменения указаний — `no`.

## Устаревание относительно гипотезы

Гипотеза изменилась — свежесть порядка проверяется:

```text
python3 "${CLAUDE_PLUGIN_ROOT}/skills/product-discovery/assets/product_state.py" \
  check <roadmap-path> --mark-stale
```

Код `2` — ожидаемый результат устаревания, не сбой: тело и версия порядка сохраняются, меняется только поле свежести. Устаревший порядок не перезаписывается молча: следующий запуск сводит его с изменившейся гипотезой, обновляет тело при необходимости и синхронизирует с `--parent`, возвращая свежесть.

## Проверка готовности

Перед записью убедись:

- у каждого элемента `Now` заполнена ссылка на созданный срез с готовностью `ready`;
- условия перехода — события, не даты;
- основание порядка объясняет текущую последовательность;
- всё убранное лежит в «Сейчас не делаем» с причиной и условием возврата;
- порядок ссылается ровно на одну гипотезу своего каталога.
