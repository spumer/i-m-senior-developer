# Idea mode — тело замысла, стадии и исходы

Справочник загружается, когда вид документа — `idea`: сырой замысел, у которого тип следующей работы ещё не выбран или выбор надо зафиксировать явно. Он владеет телом замысла, значениями метаданных и проверкой готовности. Диалог — в `references/dialogue.md`, выбор поставщика — в `references/routing.md`, общий порядок записи — в `SKILL.md`.

## Расположение

```text
<корень>/IDEA-NNNN-<slug>.md
```

Один файл, без каталога и дочерних файлов: у замысла нет технических приложений. Корень берётся из `planner-context.md` §5 — по умолчанию `ideas/`, но проект может использовать свой. Номер и полный путь выдаёт помощник командой `allocate`; номер на глаз не выбирается.

## Метаданные

Помимо общих полей замысел владеет двумя: стадией работы и решением о судьбе. Их пишет помощник при `sync`, в тело они не включаются.

```text
stage:   exploring | resolved
outcome: open | feature | epic | research | experiment | decision |
         deferred | rejected | duplicate | split
```

При `stage: resolved` к метаданным добавляется ссылка на связанный документ:

```text
target: ../epics/EPIC-0007-provider-routing/EPIC.md
```

Правила связи, проверяемые помощником (нарушение — код `3`, файл не меняется):

- `stage: exploring` — `outcome` равен `open`, поле `target` отсутствует;
- `stage: resolved` — `outcome` не может быть `open`;
- `target` обязателен для `feature`, `epic`, `duplicate`;
- для остальных решённых исходов `target` не требуется.

Существование файла по пути `target` помощник не проверяет: ссылка может указывать на документ, который создаст следующая команда.

## Тело замысла

Шаблон целиком, без пропуска разделов:

```markdown
# IDEA-0004 — Маршрутизация поставщиков

## Исходная формулировка
> дословный текст запроса

Источник: <кто или что принесло, дата, ссылка>

## Проблема и желаемый результат
Проблема: ...
Кого затрагивает: ...
Наблюдаемый желаемый результат: ...

## Рассмотренные направления
1. ...
2. ...
3. ...

## Что известно
| Утверждение | Основание | Тип | Актуальность |
|---|---|---|---|
| ... | ... | наблюдение / внешний источник / POV-гипотеза | ... |

## Допущения
| Допущение | Важность | Подтверждение | Что будет, если ложно |
|---|---|---|---|
| ... | высокая / средняя / низкая | есть / слабое / нет | ... |

## Критичное неизвестное
Что именно неизвестно: ...
Какое решение оно меняет: ...

## Точки зрения
| Точка зрения | Возможная цель или ограничение | Возможное возражение | Что надо проверить |
|---|---|---|---|

Записи в этом разделе — гипотезы, а не отзывы реальных людей.

## Следующий шаг
Действие: ...
Стоимость: ...
Обратимость: обратимо / трудно обратимо; способ отката: ...
Что различает: ...

## Решение
Исход: <feature | epic | research | experiment | decision | deferred | rejected | duplicate | split>
Цель: <путь или ссылка>
Основание: ...
Отклонённые варианты: ...
Условие пересмотра: ...
```

Заголовок — номер и краткое имя, полученные от `allocate`. Раздел «Решение» заполняется только при `stage: resolved`.

Часть исходов обязывает тело:

- `deferred` — условие возврата;
- `rejected` — основание и граница отказа;
- `split` — перечень новых замыслов с путями их файлов.

## Исходы и следующая работа

| Исход | Условие выбора | Следующая работа |
|---|---|---|
| `open` | Тип следующей работы не выбран; критичное неизвестное записано | Продолжение проработки: `/plan-idea` по этому же файлу |
| `feature` | Один результат, один независимо поставляемый срез, приёмку можно определить без общей гипотезы | `/plan-feat` |
| `epic` | Один результат требует нескольких срезов или нескольких рубежей проверки | `/plan-epic` |
| `research` | Конкретный вопрос закрывается существующими сведениями, интервью, логами или анализом | Выполнить проверку из «Следующего шага»; по результату — снова `/plan-idea` по этому файлу с новым исходом |
| `experiment` | Нужны новые наблюдения; есть опровергаемое допущение, метрика, порог и действие по каждому результату | Как `research`: проверка, затем возврат к этому же замыслу |
| `decision` | Выбирается политика или направление, а не поставляемая возможность | Решение зафиксировано в «Решении»; команда планировщика не требуется |
| `deferred` | Замысел не опровергнут, но сейчас нет appetite или не снята зависимость; условие возврата записано | Активного шага нет; `/plan-idea` при наступлении условия возврата |
| `rejected` | Есть достаточное ограниченное основание отказаться; записаны контекст и условие возможного открытия заново | Следующего шага нет |
| `duplicate` | Канонический объект уже существует; ссылка на него в `target` | Работа продолжается с объектом по ссылке `target`; команда определяется его видом |
| `split` | Вход содержит несколько независимых возможностей | `/plan-idea` для каждого нового замысла из списка |

Сырой замысел не направляется сразу в порядок работ: roadmap строится из уже сформированных срезов.

## Отсутствие подтверждений — не отказ

Отсутствие подтверждений не является основанием для `rejected`. Молчание сведений — не отрицательный результат: если допущения не подтверждены и не опровергнуты, исход — `research`, `experiment` или `deferred`, а когда решение нельзя принять честно — замысел остаётся открытым (`open`) с записанным критичным неизвестным. `rejected` требует достаточного ограниченного основания отказа и его границы в теле.

## Вызовы помощника

Только для замысла; общий порядок и решение о `--semantic-change` — в `SKILL.md`.

Новый замысел — выделить носитель (для существующего не вызывается):

```text
python3 "${CLAUDE_PLUGIN_ROOT}/skills/product-discovery/assets/product_state.py" \
  allocate idea --root <dir> --slug <slug>
```

Проверить цель до подготовки тела (`--parent` замыслу не передаётся):

```text
python3 "${CLAUDE_PLUGIN_ROOT}/skills/product-discovery/assets/product_state.py" \
  validate-target idea <path> --directory <dir>
```

Записать:

```text
python3 "${CLAUDE_PLUGIN_ROOT}/skills/product-discovery/assets/product_state.py" \
  sync idea <path> --body-file <path>.prepared \
  --semantic-change <yes|no> \
  --stage <exploring|resolved> \
  --outcome <open|feature|epic|research|experiment|decision|deferred|rejected|duplicate|split> \
  [--target <path>]
```

- `--stage` и `--outcome` обязательны: их пропуск — код `3`;
- `--target` передаётся при исходах `feature`, `epic`, `duplicate`; при `stage: exploring` его передача — код `3`;
- `--readiness` и `--state` — поля других видов, замыслу не передаются.

## Готовность замысла

Замысел готов к записи, если:

1. исходный смысл сохранён — «Исходная формулировка» дословна и с источником;
2. тип следующей работы выбран или явно оставлен открытым;
3. основание и неизвестное разделены — у каждого утверждения в «Что известно» и «Допущениях» указаны тип и носитель, критичное неизвестное названо;
4. нет ложного заявления о подтверждении — оценка «есть / слабое / нет» отражает фактический носитель, гипотеза точки зрения не названа отзывом;
5. указаны следующий шаг и условие пересмотра.

Провал любого пункта — не повод дозаполнить молча: вернись в диалог или оставь вопрос открытым.
