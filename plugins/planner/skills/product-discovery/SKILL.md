# Product discovery — проработка замысла до документа

Скилл доводит сырой вход до одного из четырёх продуктовых документов:

| Вид | Документ | Режимной справочник |
|---|---|---|
| `idea` | `ideas/IDEA-NNNN-<slug>.md` | `references/idea-mode.md` |
| `epic` | `epics/EPIC-NNNN-<slug>/EPIC.md` | `references/epic-mode.md` |
| `roadmap` | `epics/EPIC-NNNN-<slug>/ROADMAP.md` | `references/roadmap-mode.md` |
| `feature` | `features/FEAT-NNNN-<slug>/README.md` | `references/feature-mode.md` |

Один запуск — один документ. Успешный запуск не выводит документ в чат: только путь, версия, главные исходы и следующая команда.

Вид документа передаёт команда. При самостоятельной активации вид определяется по входу: свободный текст без формы — `idea`; несколько связанных фич под один результат — `epic`; вход требует упорядочить существующие фичи — `roadmap`; одна независимо поставляемая фича с проверяемой приёмкой — `feature`. При сомнении между `idea` и `feature` — `idea`: она дешевле и не обещает поставку.

## Загрузка справочников

За один запуск загружается в этом порядке:

1. `SKILL.md` — этот файл: порядок работы и границы записи;
2. `references/routing.md` — диагностика, матрица способностей, выбор поставщика, договор ответа;
3. **ровно один** режимной справочник для выбранного вида.

Одновременная загрузка двух режимных справочников запрещена: у видов разные тела документов и разные правила готовности, смешение даёт документ чужого вида.

`references/dialogue.md` и `references/pov-review.md` догружаются по ходу диалога, когда наступает их очередь работы.

## Помощник

Единый вызов:

```text
python3 "${CLAUDE_PLUGIN_ROOT}/skills/product-discovery/assets/product_state.py" <команда> [аргументы]
```

Общие правила:

- успех — одна строка JSON в stdout;
- ошибка — текст в stderr;
- коды выхода: `0` успех, `2` документ устарел, `3` нарушен договор, `64` ошибка вызова;
- при коде `3` целевой файл остаётся неизменным.

Не воспроизводи разбор метаданных, отпечатки и проверки помощника в рассуждениях — вызывай его.

## Порядок работы

### 1. Определить вид и прочитать контекст проекта

Прочитай `<project-root>/.claude/planner-context.md`. Корни продуктовых документов (`ideas/`, `epics/`, `features/` или проектные варианты) записаны в его §5. Если файла нет — следуй `plugins/planner/skills/planner/references/bootstrap.md`, затем вернись сюда. Если §5 не содержит корней продуктовых документов, используются `ideas/` и `epics/` рядом с корнем фич, и это дописывается в §5.

При работе с существующим документом сначала посмотри его состояние:

```text
python3 "${CLAUDE_PLUGIN_ROOT}/skills/product-discovery/assets/product_state.py" \
  inspect <path>
```

Документ без поддерживаемых метаданных возвращается версией `0` и не переписывается ради миграции.

### 2. Диагностика и выбор поставщика

Загрузи `references/routing.md`, затем выбери поставщика для своего вида:

```text
python3 "${CLAUDE_PLUGIN_ROOT}/skills/product-discovery/assets/product_state.py" \
  route <planner-context.md> --for <kind>
```

Код `3` — два разных случая, различай их по сообщению помощника в stderr:

- раздел §9 отсутствует или не разбирается (сообщение про секцию §9 или формат таблицы) — файл контекста отстал от формата: выполни повторное сканирование по `plugins/planner/skills/planner/references/bootstrap.md`, затем повтори `route`;
- обязательная способность не покрыта либо закреплённый поставщик отсутствует, недоступен или не даёт достаточного покрытия — останови запуск. Передай человеку из stderr помощника требуемую способность и все относящиеся строки матрицы с номером, поставщиком и причиной отклонения; закреплённого поставщика не подменяй.

До успешного `route` не вызывай поставщика и не резервируй черновик. При успехе сохрани в итоге выбранные и отклонённые строки из следа. Правила разбора матрицы, остановки и следа выбора — в `routing.md`.

### 3. Диалог

Веди сократический диалог по `references/dialogue.md`: информационные вопросы порциями, выслушать, нейтрально подытожить, синтезирующий вопрос. Значимые решения — через `AskUserQuestion` по протоколу значимого решения. Вопрос не задаётся, если ответ не меняет документ.

### 4. Зарезервировать черновик и вызвать поставщика

После успешного `route` зарезервируй черновик:

```text
python3 "${CLAUDE_PLUGIN_ROOT}/skills/product-discovery/assets/product_state.py" \
  reserve-response-draft
```

Помощник вернёт `DraftLease.path`: это единственный разрешённый временный путь с точным именем `provider-response.json` в уникальном системном временном каталоге вне репозитория.

Передай поставщику вид документа, текущую формулировку, собранные утверждения с их типом и список требуемых способностей. Передай явный запрет записи файлов: поставщик возвращает черновик в контекст, а файл не создаёт. Внешние и встроенные поставщики файлов не пишут никогда.

Если поставщик отказался или черновик не удалось записать, отмени аренду:

```text
python3 "${CLAUDE_PLUGIN_ROOT}/skills/product-discovery/assets/product_state.py" \
  release-response-draft <DraftLease.path>
```

При отсутствующем файле помощник вернёт `draft_existed: false`: это штатный исход, в котором убирать нечего. Не переходи к сборке тела.

### 5. Проверить ответ и убрать черновик

Только процедура записывает JSON-ответ по `DraftLease.path`, затем сразу проверяет и потребляет его:

```text
python3 "${CLAUDE_PLUGIN_ROOT}/skills/product-discovery/assets/product_state.py" \
  check-response <DraftLease.path> --for <kind> --consume
```

Режим `--consume` проверяет состав и удаляет черновик вместе с его временным каталогом и при принятии, и при отказе. При принятии JSON содержит `accepted: true` и `draft_removed: true`. При отказе назови полный временный путь и причину. Сообщи об удалении черновика, если уборка прошла; если она не удалась, её ошибка входит в результат и не скрывается.

Сообщение поставщика о записи файла и запрещённые заявления помощник не видит: проверь их по `routing.md`. При нарушении не используй ответ как целое; для недостающей части включи ограниченный режим с явной пометкой источника. После отказа не переходи к сборке тела.

### 6. Сборка тела

Собери тело документа только из принятого в памяти ответа по режимному справочнику: он владеет разделами, допустимыми значениями и проверкой готовности своего вида. Тело — без YAML-метаданных: их пишет помощник.

### 7. Выделить носитель при первом создании

Для нового документа вызови `allocate`. Корень бери из `planner-context.md` §5:

```text
python3 "${CLAUDE_PLUGIN_ROOT}/skills/product-discovery/assets/product_state.py" \
  allocate <kind> --root <dir> --slug <slug>
```

`roadmap` не выделяется: он живёт в каталоге общей гипотезы. Номер выбирает помощник, не ты. Поле `duplicates` в ответе — предупреждение о существующих коллизиях, не повод переименовывать.

Для существующего документа `allocate` не вызывается.

### 8. Проверить цель

```text
python3 "${CLAUDE_PLUGIN_ROOT}/skills/product-discovery/assets/product_state.py" \
  validate-target <kind> <path> --directory <dir> [--parent <path>]
```

Для `roadmap` родительский `EPIC.md` обязан лежать в том же каталоге — передавай `--parent`. Код `3` или `64` останавливает запуск до подготовки тела.

### 9. Записать подготовленное тело

Реши, меняет ли новое тело смысл:

- `yes` — изменились решения, границы, критерии, исход, порядок или состав фич;
- `no` — тело не изменилось или изменились только форматирование и формулировки без изменения указаний.

Запиши тело инструментом `Write` во временный файл с точным именем `<target-name>.prepared` рядом с целью: `IDEA-NNNN-<slug>.md.prepared`, `EPIC.md.prepared`, `ROADMAP.md.prepared`, `README.md.prepared`. Не используй другое имя, символическую или жёсткую ссылку.

### 10. Синхронизировать

Общая форма — флаги, не зависящие от вида:

```text
python3 "${CLAUDE_PLUGIN_ROOT}/skills/product-discovery/assets/product_state.py" \
  sync <kind> <path> --body-file <path>.prepared --semantic-change <yes|no> \
  <повидовые флаги>
```

Повидовые флаги и точные вызовы каждого вида — в режимном справочнике выбранного вида; здесь они не повторяются.

Помощник проверяет цель и, при `--parent`, снимает версию и отпечаток родителя — до чтения подготовленного файла. Затем читает и удаляет его, проверяет значения полей и их связи и атомарно записывает метаданные и тело вместе. Новому документу присваивается версия `1`, смысловое изменение её увеличивает.

Отказ по цели или по родителю приходит до чтения: подготовленный файл остаётся на месте, и повторный вызов не требует собирать тело заново. Отказ по недопустимому значению поля наступает уже после чтения — тело придётся подать снова.

### 11. Проверить соседний документ

После записи `epic`, если рядом лежит `ROADMAP.md`, проверь его свежесть:

```text
python3 "${CLAUDE_PLUGIN_ROOT}/skills/product-discovery/assets/product_state.py" \
  check <roadmap-path> --mark-stale
```

Код `2` — ожидаемый результат устаревания, не сбой: тело порядка сохраняется, помечается только свежесть. Отметь это в итоге.

### 12. Короткий итог

После успеха выведи только:

```text
<Вид> сохранён: <path>
Версия: <N> — <current|stale>
Главное:
- <исход 1>
- <исход 2>
- [<исход 3>]
- [<исход 4>]
Дальше: <команда вместе с аргументом — путь к файлу или каталогу>
```

Два–четыре исхода, без полного документа. Для `idea` с исходом `feature` или `epic` итог называет следующую команду, но сам её не выполняет.

Имя команды без аргумента в строке «Дальше» не выводится. Путь тогда достраивает человек, а у `/plan` по одному имени вообще не видно, какой из двух её входов имеется в виду — требования или архитектура. Подставляй путь, который этот запуск выделил или записал.

Для `feature` итог называет всю цепочку, по строке на шаг:

```text
/plan features/FEAT-NNNN-<slug>/README.md
/plan features/FEAT-NNNN-<slug>/ARCHITECTURE.md
/plan-do features/FEAT-NNNN-<slug>/
```

Шаги идут по очереди, а не разом: вторая строка читает файл, который создаёт первая.

## Граница записи

Канонический файл пишет только помощник `product_state.py`, вызванный этим скиллом.

Разрешено записывать:

1. JSON-черновик поставщика только по `DraftLease.path`, который вернул `reserve-response-draft`: это точный путь `<tempdir>/provider-response.json` вне репозитория; после проверки или отмены аренды помощник удаляет его вместе с каталогом;
2. временный `<target-name>.prepared` рядом с выбранной целью;
3. `.claude/planner-context.md` при bootstrap или явном повторном сканировании.

Перечень закрыт. `Write` создаёт JSON-черновик только процедура, а подготовленное тело — только по точному имени рядом с целью.

Запрещено:

- писать канонический документ напрямую через `Write`;
- обходить границу через оболочку, перенаправление вывода или другой инструмент;
- позволять внешнему или встроенному поставщику писать файлы — они возвращают черновик;
- удалять или переименовывать существующие документы и дубликаты номеров.

Bash используется только для вызова помощника и создания выбранного каталога.

## Ошибки маршрута, черновика и записи

Код `3` у `route` завершает запуск до аренды и вызова поставщика. Назови непокрытую способность и диагностические строки либо передай сообщение о закреплённом поставщике; не пытайся выбрать замену.

Если аренда уже создана, но ответа нет или `Write` не создал файл, вызови `release-response-draft`. Сообщи полный путь и исход отмены. Если JSON записан, но `check-response --consume` вернул код `3`, назови полный временный путь, причину отказа и результат уборки; новый документ не создавай.

Ошибка `Write` подготовленного тела или код `3`/`64` у `sync` означает: новый документ не сохранён, прежний файл остался текущим результатом.

1. Назови путь цели и конкретную ошибку.
2. Скажи, что результат не сохранён и остался ли прежний файл.
3. Выдай подготовленный текст документа в чат целиком — это запасной результат.
4. Не выводи успешный итог и не пытайся записать тело в цель как восстановление.

Не глотай ошибку и не продолжай с устаревшими метаданными.

## Чего скилл не делает

- Не строит архитектуру и не реализует: это работа `/plan` и `/plan-do` по готовым требованиям фичи.
- Не выполняет следующую команду сам: итог её называет, запуск остаётся за человеком.
- Не меняет порядок фич вне вида `roadmap`.
- Не оценивает качество поставщика: выбор идёт по покрытию и доступности из матрицы §9 по правилам `routing.md`, а не по качеству его ответа.

## Индекс справочников

- `references/routing.md` — матрица способностей, порядок выбора, след выбора, договор ответа поставщика.
- `references/dialogue.md` — сократический протокол и протокол значимого решения.
- `references/pov-review.md` — точки зрения как гипотезы.
- `references/idea-mode.md` — тело замысла, стадии и исходы.
- `references/epic-mode.md` — тело общей гипотезы и проверка готовности.
- `references/roadmap-mode.md` — три горизонта и условия перехода.
- `references/feature-mode.md` — требования фичи и критерии приёмки.
