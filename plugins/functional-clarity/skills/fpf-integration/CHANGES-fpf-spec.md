F.12 — Service Acceptance Binding (привязка SLO/SLA и acceptance criteria к фактической работе через KD-CAL).

- **Новые паттерны именования и переписывания прозы (свежие дополнения F.IV)** (F.18, F.19): Два наиболее новых и отличающихся паттерна. F.18 (Local-First Unification Naming Protocol) — протокол именования: имя есть handle для использования, а не создатель онтологии; первый ход — восстановить governed value до выбора имени; вводит NameCard (GovernedValueRef, GoverningPatternRef, BoundedContextRef, LocalSenseRef, Tech/Plain-метки, CandidateSet, SelectionRationale, Lineage) и UnifiedTermRow для публичных/Core-facing/durable/кросс-контекстных имён; борется с тем, что role-looking/status-like/evidence-like имена тайно протаскивают онтологию. F.19 (Ontology-First Plain Technical Rewriting) — ремонт технической прозы, где объект/claim/relation/action погребены под «apparatus» (роль-язык, контейнерные слова, статус-слова, process-traces, повторяющиеся негативные каталоги, reference-boilerplate, метафоры применения паттернов): сначала разделить content и apparatus по онтологии, затем писать кратчайшую plain technical форму, сохраняя FPF-kinds, слоты, границы claim и admissible use; это НЕ косметическое упрощение языка.
