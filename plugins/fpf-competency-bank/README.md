# fpf-competency-bank

Задаёт правила, по которым компетенция попадает в банк, и служит источником
готовых сводов для `fpf-integration`. Резолвер `dpf-apply` находит банк на
плагинном уровне — нижнем из трёх, так что одноимённый свод проекта или
пользователя банковский перекрывает. Этот файл отвечает на устройство
плагина в репозитории; договор — что даёт банк, границы применения сводов, допуск
и измеренная зрелость — на странице
[`docs/plugins/fpf-competency-bank.md`](../../docs/plugins/fpf-competency-bank.md).

Плагин хранит данные банка и объявляет обработчик `SessionStart` с командой
публикатора пути. Публикатор заменяет содержимое
`~/.claude/frameworks.published` строкой `<CLAUDE_PLUGIN_ROOT>/frameworks`.
Резолвер, гейт свежести и скрипт профиля зрелости живут в `fpf-integration`;
журналы worked-evidence лежат здесь, в `references/` каждого пакета. Что значат
«свод», «компетенция», DPF, LPF, ground/apply, затенение и протухание — словарь
в README плагина `fpf-integration`, раздел «Словарь». Здесь термины не
пересказываются.

## Что внутри

| id | kind | modes | назначение |
|----|------|-------|-----------|
| `DPF-COUPLING-GENERALIZATION` | Domain Principle Framework | knowledge | когда более крупная правка сокращает связи между объектами — доменный свод, применим без форка на решении «обобщать существующее дублирование или нет» |
| `LPF-SIMPLIFICATION-REVIEW` | Local Practice Framework | executable | ревью-обобщение диффов на стадии «Упрощение» — образец класса LPF; ограничения применения — на странице договора |

Полная карта с cue-словами для UserPromptSubmit-хука — `frameworks/competency-map.md`.
Критерии допуска пакета в банк (различение DPF/LPF, fail-closed гейт) —
`CONTRIBUTING.md` рядом с этим файлом.

## Подключение

Резолвер `dpf-apply` ищет банки на трёх уровнях: project
(`$PWD/.claude/frameworks`), user (`~/.claude/frameworks`) и plugin. На уровне
plugin он читает корни сначала из человеческого `~/.claude/frameworks.paths`,
затем из машинного `~/.claude/frameworks.published`. Повторные корни по
каноническому пути отбрасываются, поэтому сохраняется первое вхождение.
Выигрывает первый уровень, на котором нашёлся id.

Этот плагин объявляет обработчик `SessionStart`, команда которого запускает
публикатор. Публикатор полностью заменяет `frameworks.published` путём до
`frameworks` текущей установки плагина. `frameworks.paths` он не читает и не
перезаписывает: этот файл остаётся списком дополнительных человеческих путей.

Проверить объявленные корни, их происхождение и наличие каталогов можно режимом
`--sources`; он завершается кодом `0`, в том числе для отсутствующего каталога.
Проверить допуск конкретного свода можно режимом `--verify <id> --scope bank`.
Установленный плагин лежит по пути вида
`~/.claude/plugins/cache/<маркетплейс>/<плагин>/<версия>/`:

```
python3 ~/.claude/plugins/cache/i-m-senior-developer/fpf-integration/<версия>/skills/dpf-apply/scripts/resolve.py --sources
```
