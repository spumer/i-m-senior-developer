# Intellect Stack — 5 когнитивных слоёв

> Источник: FPF Practical Tools §5, адаптация для текстовых документов.

## Слои

| # | Слой | Вопрос | Примеры утверждений |
|---|------|--------|---------------------|
| 1 | **Structure** | Из чего состоит? | «Пайплайн CI состоит из трёх стадий: линтер, тесты, сборка» / «Шаблон PR имеет 6 секций» |
| 2 | **Knowledge** | Что мы знаем / наблюдаем? | «Покрытие тестами показывает, какие ветки исполняются» / «Большинство PR проходят за 2 итерации ревью» |
| 3 | **Action** | Что конкретно делать? | «Не правь сгенерированные файлы» / «Запусти линтер локально» / «Двигай задачу по доске» |
| 4 | **Strategy** | Зачем и как выбирать? | «Если тесты упали на флаки — перезапусти, не блокируй мерж» / «Линтер не пропускаем» |
| 5 | **Governance** | Кто решает, как координируем? | «Апрув ставит ревьюер секции» / «Финальное решение о релизе — за релиз-менеджером и командой» |

## Тест принадлежности

Для каждого утверждения в тексте — один вопрос:

- «Могу наблюдать/измерить?» → **Knowledge**
- «Должен сделать?» → **Action**
- «Выбираю между вариантами?» → **Strategy**
- «Описываю состав/структуру?» → **Structure**
- «Описываю кто решает / как координируем?» → **Governance**

## Правила

1. **Одна секция = один слой.** Если секция называется «Что проверяет стадия» — в ней только Knowledge. Если «Что делать» — только Action.
2. **Нет скачков через слой.** Переход Knowledge → Strategy (минуя Action) = пропущен шаг. Читатель не понимает что делать с этим знанием.
3. **Императив = Action/Strategy.** Если предложение обращается к читателю («не правь», «решаем по», «перезапусти») — оно не может быть в описательной секции.
4. **Таблицы: колонка = слой.** Колонка «Что проверяет» не должна содержать «Решаем по линтеру».

## Типичные ошибки

### Смешение Knowledge + Strategy в одном абзаце

```
❌ Покрытие тестами показывает, какие ветки исполняются.
   Если покрытие < порога — блокируем мерж.
```

Первое предложение — Knowledge (что наблюдаем). Второе — Strategy (как принимать решение). Разные слои в одном абзаце.

```
✅ Секция «Что показывает»:
   Покрытие тестами показывает, какие ветки исполняются.

   Секция «Правило мержа»:
   Если покрытие критичного модуля < порога — мерж блокируем.
```

### Action зарыт в описание

```
❌ Сильный PR — атомарные коммиты, понятные сообщения.
   Не рефактори соседний модуль сам — это отдельная задача.
```

«Не рефактори» — Action, но он вклеен в описание критерия (Knowledge/Strategy). Читатель споткнётся.

```
✅ Критерий «сильный PR»:
   Атомарные коммиты, понятные сообщения, изменение в границах задачи.

   (Инструкция уже в секции «Чего не делаем в этом PR»:
   Рефакторинг соседних модулей — отдельная задача.)
```

### Дублирование вывода в двух секциях

```
❌ Секция «Что даёт стадия»: Падение тестов — не приговор, решаем по характеру падения.
   Секция «Правило мержа»: Тесты упали, но падение на флаки → мержим после перезапуска.
```

Одно и то же решение сформулировано дважды разными словами в разных секциях. Читатель не знает, где каноническая версия.

```
✅ Секция «Что даёт стадия»: только Knowledge (что стадия показывает).
   Секция «Правило мержа»: все выводы один раз.
```
