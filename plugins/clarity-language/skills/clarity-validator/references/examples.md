# Каталог находок и исправлений

> Иллюстративные примеры на нейтральном домене (документация проекта, API,
> contribution-гайды, онбординг в инструмент). Каждая запись: что было, что стало,
> почему, какой паттерн. Сверяйся при проверке — чаще всего текущая проблема уже
> встречалась в этом каталоге.

## Из гайда по онбордингу в проект

### Ссылка на несуществующий файл

```
❌ Настрой окружение по чек-листу (зафиксирован в аудите SETUP.md)
```
**Диагноз:** Паттерн 10 (ссылка на несуществующее). Файла `SETUP.md` в репозитории нет. AI выдумал ссылку.

```
✅ Настрой окружение: установи зависимости и прогони smoke-тест
```

---

### Action вклеен в критерий

```
❌ Принять PR | Изменение покрыто тестами, не ломает контракт.
   Не рефактори соседний модуль сам — это отдельная задача
```
**Диагноз:** Смешение слоёв (Паттерн 7, Strict Distinction). Инструкция «не рефактори» вклеена в Strategy-таблицу критериев приёмки. Критерий решения и инструкция что делать — разные слои.

```
✅ Принять PR | Изменение покрыто тестами, не ломает публичный контракт,
   на ревью не нашлось блокеров
```

### Дублирование вывода в двух секциях

```
❌ Секция «Что проверяет CI»:
   | Линтер | Основная проверка. Если линтер красный — мерж заблокирован |

   Секция «Правила мержа»:
   | Мерж с оговоркой | Линтер упал, но падение на сгенерированном файле,
     не на коде автора |
```
**Диагноз:** Паттерн 12. Одно правило в двух местах разными словами. Обновят одну формулировку — вторая отстанет.

```
✅ Секция «Что проверяет CI»:
   | Линтер | Статический анализ стиля и типов |

   Секция «Правила мержа»:
   | Мерж с оговоркой | Линтер красный, но только на сгенерированном файле |
```

## Из contribution-гайда

### Выдуманный флоу

```
❌ Если сомневаешься в подходе — открой issue. Бот автоматически назначит
   ревьюера из core-команды, и вы вместе примете решение.
```
**Диагноз:** Паттерн 4. Никакой бот ревьюеров не назначает — это выдуманный флоу.

```
✅ Если сомневаешься в подходе — открой issue, опиши развилку и варианты.
   Отметь maintainers секции, которую затрагиваешь.
```

---

### Плейсхолдер без привязки к флоу

```
❌ Шаблон: «Сомневаюсь по [причина], хочу согласовать с [имя],
   дедлайн [дата]»
```
**Диагноз:** Паттерн 3. Контрибьютор не знает конкретного «имени» — он пишет в issue и отмечает владельцев секции. Плейсхолдер `[имя]` предполагает флоу «я знаю кого пинговать», которого нет.

```
✅ Открой issue, опиши в чём сомневаешься, отметь maintainers затронутой
   секции.
```

---

### Старая терминология, не синхронизированная с шаблоном

```
❌ Статус: берём / не берём / на доработку
```
**Диагноз:** Паттерн 12 (рассогласование между файлами) + Паттерн 7 (design/run-time). Старая формулировка из ранних обсуждений, не совпадает с лейблами в шаблоне PR.

```
✅ Статус: выставить лейбл из набора шаблона PR (ready-to-merge /
   changes-requested / rejected). В комментарии — своими словами,
   с обоснованием
```

## Из раздела «Сопровождение релизов»

### Negation of nothing

```
❌ Назначение релиз-менеджера — решение команды, не автоматическая
   процедура. Без триггеров по дням.
```
**Диагноз:** Паттерн 1. В разделе про назначение релиз-менеджера никаких «дневных триггеров» никогда не обсуждалось. Это residual от удалённой дискуссии про SLA. Leaked invariant из другого bounded context.

```
✅ Назначение релиз-менеджера — решение команды.
```

---

### Ещё одно negation of nothing

```
❌ Эскалация при долгом молчании ревьюера: автор обращается к лиду секции.
   Лид сам решает: подождать, написать, переназначить.
   Без автоматических правил «Х дней → переназначение».
```
**Диагноз:** Паттерн 1. Такой же leaked invariant. В контексте эскалации правил «Х дней → переназначение» никто не устанавливал.

```
✅ Эскалация при долгом молчании ревьюера: автор обращается к лиду секции.
   Лид сам решает: подождать, написать, переназначить.
```

### Имитация авторитета через диапазон часов

```
❌ Честные трудозатраты: полный цикл миграции — ≈15-20 часов за ~2 спринта.
```
**Диагноз:** Паттерн 5. Диапазон часов — оценка из ранней сессии, не реальное измерение. Источник не указан.

```
✅ (разделить на измеримые компоненты)
   - Подготовка схемы миграции — оценить по числу таблиц
   - Прогон на staging + проверка инвариантов
   - Согласование окна простоя
   - Применение на production + мониторинг

   Цикл растягивается на ~2 спринта. Реальные трудозатраты зависят от
   объёма данных и числа зависимых сервисов — прикинь по списку под свой
   контекст.
```

### Панибратский тон

```
❌ Точные дедлайны не прописаны: все мы ребята занятые, но давайте
   уважать друг друга.
```
**Диагноз:** Паттерн 8. Фамильярный тон в публичной документации (если это не осознанный авторский стиль — см. `russian-style`, правило 4).

```
✅ Точные дедлайны не прописаны — срок определяется загрузкой команды.
```

---

### Перегрузка будущим функционалом

```
❌ ### Учёт в метриках качества: количество и качество

   Запись состоит из двух частей:
   - N — количество мержей...
   - Показатель качества — композит из двух величин (формула заложена,
     заполнение отложено до накопления данных):
     - Доля PR без откатов за 30 дней...
     - Отклонение времени ревью от медианы...
   На старте показатель качества = N/A.
   Качественная часть добавлена не для отчётности, а чтобы убрать стимул
   гнать количество мержей.
```
**Диагноз:** Паттерн 7 (design/run смешение) + дублирование design-time обсуждений в публичном документе. Читателю эти детали сейчас не нужны — они вступят в силу позже.

```
✅ В метриках учитывается количество мержей и качество (доля PR без откатов,
   время ревью). Детали показателя качества уточняются после накопления
   данных — на старте учитывается только количество.
```

### Термин без пояснения

```
❌ Издержки на мейнтенанс сервиса высокие
```
**Диагноз:** Паттерн 6 (неуместная иноязычная вставка). «мейнтенанс» дублирует точное русское «сопровождение» и не несёт нового смысла — это калька, не устоявшееся заимствование.

```
✅ Издержки на сопровождение сервиса высокие
```

> Контрпример (НЕ паттерн 6): «p95 (95-й перцентиль времени ответа) ≥ цели» —
> это термин-жаргон, допустимый с пояснением при первом упоминании. Спорные
> случаи выносить Человеку (см. паттерн 6 в `synthetic-patterns.md`).

## Паттерны по частоте (из этого набора)

> Частоты ниже — иллюстративные (подсчёт по этому каталогу примеров), не измерение
> на реальном корпусе. Не цитировать как статистику (иначе сам попадёшь в паттерн 5).

| Паттерн | Частота | Критичность |
|---------|---------|-------------|
| Дублирование вывода (12) | 4 раза | высокая |
| AI-метки провенанса (2) | 6+ раз | средняя |
| Имитация авторитета через цифры (5) | 4 раза | высокая |
| Смешение слоёв (7) | 5 раз | высокая |
| Плейсхолдеры без флоу (3) | 2 раза | высокая |
| Выдуманный флоу (4) | 2 раза | критическая |
| Negation of nothing (1) | 2 раза | средняя |
| Ссылка на несуществующее (10) | 1 раз | высокая |
| Панибратский тон (8) | 1 раз | низкая |
| Неуместная иноязычная вставка (6) | 5+ раз | низкая |

**Вывод:** чаще всего AI совершает **Паттерны 12, 2, 5, 7** — это первые кандидаты на автоматическую проверку при каждом новом тексте.
