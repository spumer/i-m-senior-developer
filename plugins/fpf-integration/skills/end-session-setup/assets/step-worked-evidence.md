# Шаг worked-evidence (канонический текст для вставки)

> Местозаполнитель `<каталог-сводов>` заменяется фактическим каталогом сводов
> проекта (`project/frameworks` или `.claude/frameworks`). Заголовок и номер шага
> подстраиваются под протокол хозяина; текст ниже — смысловой канон.

---

**Worked-evidence сводов.** Привяжи события сессии к паттернам применявшихся
сводов — журнал каждого пакета: `<каталог-сводов>/<ID>/references/worked-evidence.md`.

1. **Закрой висящие исходы.** Открой журналы применявшихся сводов; записи с
   исходом `TBD` (включая прошлые сессии) подними списком: каждому проставь
   исход (подтверждает / опровергает / показал границу) или явно отложи с
   причиной. Молча не пропускай.
2. **Ретроспектива сессии** (обязательна, даже если dpf-apply не
   вызывался): какие паттерны каких сводов в сессии применялись или провалились
   напрямую — агент читал свод сам, без dpf-apply? Допиши такие события с
   меткой `direct`.
3. **Не дублируй.** Если событие уже есть авто-записью dpf-apply (тот же
   якорь, тот же пакет) — проставь исход в неё, новую строку не создавай.
4. **Формат строки** (един для всех писателей, не переформулировать):

   ```
   - YYYY-MM-DD · <якорь: сессия | MR/коммит/файл> · ground|apply|direct · Паттерн N «имя» · что произошло (1-2 фразы) · исход: подтверждает / опровергает / показал границу / TBD
   ```

Правила:

- «никакие своды не применялись» — валидный ответ; отчёты о неприменении не
  пишутся, все своды подряд не прочёсываются;
- в `DPF.md` не писать — это носитель свода без процессного состояния; журнал
  живёт только в `references/worked-evidence.md` пакета;
- опровержения ценнее подтверждений: опровергающая запись — кандидат на правку
  свода, занеси его в бэклог проекта (или создай задачу).
