# /end-session — закрытие сессии (полный протокол)

> Шаблон для «core team» проектов (есть `project/` с ledger и sessions).
> Местозаполнитель `<каталог-сводов>` заменяется при установке. Названия
> каталогов ledger/sessions подстрой под фактическую структуру проекта.

Закрой сессию по шагам. Пропуск шага — только осознанный, с одной строкой
«почему пропущен».

## Шаг 1. Итог сессии

Что сделано, что осталось, что заблокировано. Коротко, фактами.

## Шаг 2. Опыт

Что нового узнали в этой сессии: сработавшие приёмы, грабли, неожиданности.
То, что стоит помнить, даже если задача закрыта.

## Шаг 3. Handoff следующей сессии

Запиши в `project/sessions/` (или каталог сессий проекта): состояние работы,
следующий шаг, открытые вопросы. Пиши для человека, который ничего не помнит
об этой сессии.

## Шаг 4. Ledger

Решения сессии — в реестр решений проекта (`project/ledger` или аналог):
что решили, почему, какие альтернативы отклонили.

## Шаг 5. Worked-evidence сводов

Привяжи события сессии к паттернам применявшихся сводов — журнал каждого
пакета: `<каталог-сводов>/<ID>/references/worked-evidence.md`.

1. **Закрой висящие исходы.** Открой журналы применявшихся сводов; записи с
   исходом `TBD` (включая прошлые сессии) подними списком: каждому проставь
   исход (подтверждает / опровергает / показал границу) или явно отложи с
   причиной. Молча не пропускай.
2. **Ретроспектива сессии** (обязательна, даже если dpf-apply не
   вызывался): какие паттерны каких сводов в сессии применялись или провалились
   напрямую — агент читал свод сам, без dpf-apply? Допиши такие события с
   меткой `direct`.
3. **Не дублируй.** Если событие уже есть авто-записью dpf-apply (тот же
   якорь, тот же пакет) — проставь исход в неё, новую строку не создавай.
4. **Формат строки** (един для всех писателей, не переформулировать):

   ```
   - YYYY-MM-DD · <якорь: сессия | MR/коммит/файл> · ground|apply|direct · Паттерн N «имя» · что произошло (1-2 фразы) · исход: подтверждает / опровергает / показал границу / TBD
   ```

Правила: «никакие» — валидный ответ, все своды подряд не прочёсываются; в
`DPF.md` не писать; опровержения ценнее подтверждений — опровергающая запись
уходит кандидатом на правку свода в бэклог проекта.

## Шаг 6. Память

Обнови заметки/память проекта: факты, которые понадобятся за пределами этой
задачи (договорённости, соглашения, лексикон).

## Шаг 7. Git-гигиена

Незакоммиченные изменения: закоммить осмысленным сообщением или явно оставь с
пометкой почему. Мусорные файлы — убери.
