# Прецеденты ручных установок шага worked-evidence

Четыре ручных прогона (2026-07-14) до появления этого скилла — источник
merge-дисциплины. Обращайся сюда при выборе способа вставки.

## 1. Простой линейный протокол → полноценный шаг с перенумерацией

Проект с коротким end-session из нескольких нумерованных шагов. Шаг
worked-evidence вставлен полноценным шагом после итогов; последующие шаги
перенумерованы. Перенумерация безопасна, потому что перекрёстных ссылок на
номера шагов в протоколе не было.

**Правило:** мало шагов и нет ссылок на номера — вставляй полноценный шаг,
перенумеруй хвост.

## 2. Богатый протокол → буквенный подшаг, без перенумерации

Протокол со многими шагами и внутренними ссылками. Вставка полноценного шага
потребовала бы перенумерации половины документа и правки ссылок — вместо этого
шаг добавлен буквенным подшагом («Шаг 5c») к соседнему по смыслу шагу. Якорь
записей адаптирован под каталожные сессии проекта.

**Правило:** много шагов или есть ссылки на номера — буквенный подшаг, ноль
перенумераций.

## 3. Трёхуровневый протокол → только в уровни с расширенными шагами

Протокол с уровнями «Полный / Стандартный / Минимальный». Шаг вставлен в
«Полный» и «Стандартный» — туда, где уже есть расширенные шаги. В «Минимальный»
не вставлен: минимальный уровень существует, чтобы закрыть сессию за минуту, и
дополнительный шаг разрушил бы его назначение.

**Правило:** многоуровневый протокол — шаг только в уровни с расширенными
шагами.

## 4. Код-репозиторий → лёгкий протокол + секция в правилах

Репозиторий без сессионного процесса, но с правилом о сводах (PUR-записи в
`rules/frameworks.md`). Поставлен лёгкий end-session (якорь — MR/коммит) и
секция worked-evidence в правила рядом с PUR-записями — с явным различием:
PUR — проспектива, журнал — ретроспектива. PUR-записи не тронуты и не
продублированы.

**Правило:** в код-репозитории якорь — MR/коммит; секция правил ставится рядом
с существующими PUR-записями, не вместо них.

## Общие наблюдения всех прогонов

- Кириллические пути проектов работают без специальной обработки.
- Вставка всегда после шага итогов/опыта и до git-гигиены/закрытия.
- Чужой текст ни разу не переформулировался — только вставка (и перенумерация в
  прецеденте 1).
