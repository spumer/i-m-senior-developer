# Отчёт: planner

Проверяется продуктовый слой: попадает ли сырой замысел в проработку и
соблюдает ли встроенный поставщик свои ограничения.

## Последний прогон

| Параметр | Значение |
|---|---|
| Дата | 19.08.2026 |
| Claude Code | `2.1.234` |
| Версия плагина | `1.1.0` |
| Модель | `opus`, судья `haiku` |
| Порог | `1.0` (строгий) |
| Стоимость | `$3.06` |
| Длительность | 17 минут |
| `partial` | `false` |

Итог: **проверка проходит**.

| Кейс | Оценка | Успешных повторов |
|---|---|---|
| `baseline-provider-limits` | `1.00` | 3 из 3 |
| `idea-routing` | `1.00` | 3 из 3 |
| `multi-step-input` | `1.00` | 3 из 3 |

## Что покрыто

- `idea-routing` — сырой замысел попадает в продуктовую проработку, а не сразу
  в требования среза.
- `multi-step-input` — вход из нескольких самостоятельных исходов не
  сворачивается в один срез.
- `baseline-provider-limits` — встроенный поставщик называет свои ограничения,
  не заявляет исследование пользователей и не пишет файлы, хотя запись ему
  разрешена кейсом.

## История: как проверка стала зелёной

Первый полный прогон был красным, и это оказалось находкой, а не сбоем.

1. **Маршрутизация не срабатывала вовсе.** Скилл `product-discovery` не
   вызывался ни в одном из шести повторов. Инструмент `Skill` и сам скилл при
   этом были доступны в трассе, то есть механизм доставки работал.
2. **Модель оказалась значимым условием.** На `sonnet` вызова не было ни разу;
   на `opus` те же кейсы начали вызывать скилл. Закрепление `sonnet` измеряло не
   ту среду, поэтому проверка переведена на `opus`.
3. **Формулировки описания дали неустойчивый результат.** После правок описания
   `idea-routing` стал проходить, а `multi-step-input` срабатывал 1 раз из 3.
   Устойчивости 3 из 3 переписывание описания не давало.
4. **Устойчивость дал структурный механизм.** В плагин добавлен хук
   `UserPromptSubmit`, который опознаёт продуктовый вход по явным признакам и
   требует вызвать скилл до ответа. После этого прогон стал зелёным.
5. **Один повтор ранее падал по таймауту 180 с.** Работающий скилл занимает
   больше времени, поэтому `timeout_seconds` у маршрутизационных кейсов поднят
   до 300.

## Известные ограничения

- Проверка подтверждает поведение на `opus`. На `sonnet` маршрутизация в
  проработку не наблюдалась — это ограничение плагина, а не проверки.
- Сообщение `error: exit 1: (no stderr)` у части успешных повторов ожидаемо:
  скилл доходит до вопроса человеку, а в headless-режиме `AskUserQuestion`
  недоступен. Договор повтора задают критерии и оценка, а не этот код.
- Живой сократический диалог, интерактивный выбор человека и проверка готовности
  документа в конце диалога одношаговыми кейсами не покрываются.
