# Отчёты по проверкам плагинов

Один плагин — один отчёт. Правила проверок — в разделе
[Проверка плагинов](../testing/index.md).

## Отчёты

- **[planner](planner.md)** — продуктовый слой, маршрутизация замысла в
  проработку, ограничения встроенного поставщика.

## Что обязан содержать отчёт

Отчёт описывает наблюдённый прогон, а не замысел проверки:

1. версия Claude Code и версия плагина;
2. дата прогона, полная стоимость, признак `partial`;
3. таблица кейсов: оценка и число успешных повторов;
4. причина каждого отказа — наблюдаемая, из результата прогона;
5. что осталось открытым и чьё решение требуется.

Утверждение «проверка проходит» допустимо только при зелёном полном прогоне.
Пилотный запуск с одним повтором в отчёт как успех не идёт.

## Как обновить отчёт

Порядок описан в разделе
[Как запускать проверки](../testing/running.md). Кратко: прогнать
`evals/run.py` нужного плагина, взять из свежего `aggregate-result.json`
фактические числа и заменить ими таблицу в отчёте.
