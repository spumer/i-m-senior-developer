# plugin-testing

Поведенческая проверка плагинов для Claude Code: скилл ведёт работу от выбора
вида проверки до чтения упавшего прогона и записи отчёта. При нём справочники по
каждому шагу и утилита, которая читает eval-набор без расхода токенов.

## Состав

| Компонент | Что даёт |
|---|---|
| скилл `plugin-testing` | порядок работы: что проверять структурно, что поведением, как собрать кейс, как прочитать красный прогон |
| `check_eval_suite.py` | разбирает готовый набор и показывает пустые проверки |

Справочники скилла:

| Справочник | О чём |
|---|---|
| `validate` | `claude plugin validate` и его измеренные границы |
| `graders` | шесть видов критериев и их ловушки |
| `wrapper` | обёртка прогона: почему нулевого кода выхода недостаточно |
| `failures` | что делать, когда прогон упал |
| `deterministic-routing` | когда формулировки не держат и нужен хук |
| `early-access` | гейт раннего доступа к `plugin eval` |
| `report` | что обязан содержать отчёт о прогоне |

## Как пользоваться

### Когда включается скилл

Скилл подключается сам, когда речь о проверке плагина: собрать
поведенческий кейс, добавить критерий, прогнать набор, понять, почему скилл не
включается на живом запросе, разобрать упавший прогон, поставить гейт перед
выпуском. Точные пусковые формулировки живут в самом скилле, страница их не
повторяет.

### Утилита

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/plugin-testing/scripts/check_eval_suite.py" \
  plugins/<плагин>
```

Находит проверки, которые проходят всегда:

- кейс без критериев;
- неизвестный вид критерия;
- `max: 0` без `min: 0`;
- запрет инструмента, который кейс не запрашивает;
- дублирующееся имя критерия.

Коды выхода: `0` — замечаний нет, `1` — есть, `64` — неверный вызов.

## Границы

- Структурную проверку плагина скилл на себя не берёт: её делает
  `claude plugin validate --strict` — бесплатно и детерминированно.
- `plugin eval` платный и требует включённого раннего доступа, поэтому в CI его
  нет.
- Своего eval-набора у плагина нет: он поставляет методику и утилиту. Утилита
  покрыта обычными тестами — каждое замечание из списка выше закреплено отдельным
  случаем. Почему свой набор нужен не каждому плагину —
  [решение 5](../decisions.md).
