# llms-keeper

Контекст проекта для ИИ-инструментов: `llms.txt` и `llms-full.txt` по стандарту
[llmstxt.org](https://llmstxt.org). Плагин обходит репозиторий — код,
конфигурацию, тесты, CI, документацию — и собирает из него два файла, которые
агент читает вместо повторного обхода дерева.

## Состав

| Компонент | Что делает |
|---|---|
| команда `/update-docs` | создаёт или обновляет оба файла |
| скилл `llms-keeper` | формат и правила отбора содержания |
| агент `documentation-keeper` | читает код, конфигурацию, тесты, CI, документацию и пишет файлы |
| хук `SessionStart` | сообщает, есть ли контекстные файлы в проекте |

## Как пользоваться

### Результат

| Файл | Назначение | Размер |
|---|---|---|
| `llms-full.txt` | самодостаточный контекст проекта | 200–600 строк |
| `llms.txt` | навигационный индекс, без блоков кода | 50–100 строк |

Оба пишутся в корень проекта.

### Повторный запуск

Агент дописывает в конец `llms-full.txt` колонтитул с датой и коммитом, на
котором собран файл. При следующем запуске он читает этот коммит и обновляет
только затронутые с тех пор разделы. Если колонтитула нет или он не
разбирается, агент берёт последние 20 коммитов.

### Что в файлы не попадает

Обучающие материалы, временные обходы, `TODO`/`FIXME`, паттерн из одного файла,
многословные объяснения, очевидные сведения, отладочный вывод, номера строк,
статусы открытых задач, отдельные тест-кейсы, любые секреты.

## Границы

- Файлы рассчитаны на ИИ-инструменты. README для человека плагин не заменяет и
  не пишет.
- Инкрементальное обновление держится на истории коммитов: без git каждый запуск
  собирает оба файла целиком.
- Файл — снимок состояния. При расхождении с кодом правдой остаётся код.
