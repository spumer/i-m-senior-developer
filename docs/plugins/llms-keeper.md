# llms-keeper: контекст проекта для ИИ-инструментов

## Что это

Команда `/update-docs`, скилл, агент и хук на старт сессии. Хук сообщает, есть ли
в проекте контекстные файлы, и если нет — предлагает команду.

Агент читает исходный код, конфигурацию, тесты, CI и документацию и пишет в
корень проекта два файла по стандарту llmstxt.org:

- `llms-full.txt` — самодостаточный контекст проекта, 200–600 строк;
- `llms.txt` — навигационный индекс, 50–100 строк.

Повторный запуск не переписывает всё заново: агент смотрит изменения в git и
обновляет только затронутые разделы. Если нижний колонтитул прошлого файла
отсутствует или не разбирается, он берёт последние двадцать коммитов вместо
диапазона от записанного коммита.

## Для чего это

Любой ИИ-инструмент начинает работу с нуля: он не знает стек, границы модулей,
принятые соглашения и то, где лежат тесты. Контекстный файл переносит это знание
из чужой головы в репозиторий, где оно версионируется вместе с кодом.

Что в файл сознательно не попадает: обучающие материалы и инструкции по
внедрению, временные обходы, `TODO` и `FIXME`, паттерн, встречающийся в одном
файле, многословные объяснения, очевидные сведения, отладочная информация,
номера строк, статусы текущих задач, отдельные тест-кейсы и любые секреты. Файл
даёт ориентиры, а не заменяет чтение кода.

## Как пользоваться

```text
/update-docs
```

Команда работает и на пустом месте, и на существующих файлах. Отдельного
согласования формата не требуется — он задан стандартом.

## Когда НЕ пользоваться

- **Как документация для людей.** Формат рассчитан на ИИ-инструменты. Человеку
  нужен README и разделы этого сайта.
- **Как место для секретов и учётных данных.** Прямо исключено; файл попадает в
  репозиторий.
- **Как замена актуальному коду.** Файл — снимок состояния; при расхождении
  правдой остаётся код, а файл нужно обновить.
- **Проект без git.** Обновление опирается на историю коммитов; без неё каждый
  запуск будет полной перегенерацией.
