# llms-keeper

Помогает держать контекст проекта для ИИ-агентов в актуальном виде — файлом,
который читается за один раз, по стандарту llmstxt.org.

## Основные возможности

- Собирает картину проекта — архитектуру, стек, соглашения и точки входа — так,
  чтобы агент получал её за одно чтение вместо блуждания по каталогам.
- Встаёт в цикл разработки как хранитель документации: после завершения фаз
  реализации обновление вызывает сам `planner`, передавая разрешённые планом
  пути.
- Обновляет только те разделы, которых коснулись изменения с прошлого снимка.
- Даёт два уровня подробности: короткий `llms.txt` со ссылками и полный
  `llms-full.txt` с содержанием.

**Важно:** используйте команду `/update-docs` для актуализации в любой момент —
можно указать область фокуса или `full` для полной пересборки.

## Состав

Контекст проекта для ИИ-инструментов: `llms.txt` и `llms-full.txt` в корне
репозитория. Плагин состоит из промптов и одного хука: дерево обходит и файлы
пишет модель по инструкции агента, поэтому состав и объём файлов зависят от
прогона.

Формат `llms.txt` взят из [llmstxt.org](https://llmstxt.org): H1 с именем
проекта, цитата-сводка, разделы H2 со списками ссылок, раздел `Optional` для
второстепенного. Обязательным стандарт считает только H1, цитату-сводку требует
уже справочник плагина. `llms-full.txt` стандарт не описывает — это отраслевая
договорённость, и правила для него задаёт тот же справочник.

## Состав

| Компонент | Что делает |
|---|---|
| команда `/update-docs` | просит модель вызвать агента `documentation-keeper` и передаёт область внимания из аргумента |
| скилл `llms-keeper` | формат обоих файлов, правила отбора содержания, справочник по стандарту; работу отдаёт тому же агенту |
| агент `documentation-keeper` | инструкция: определить стек по файлам манифеста, перечислить каталоги верхнего уровня, прочитать в порядке приоритета точки входа, ядро, конфигурацию, структуру тестов, документацию и CI, записать оба файла |
| хук `SessionStart` | проверено запуском: печатает одно из трёх сообщений — есть `llms-full.txt`, есть только `llms.txt`, нет ни одного, — в каждом советует `/update-docs` и выходит с кодом `0` |

## Как пользоваться

### Результат

Оба файла пишутся в корень проекта. Длины и имена разделов — ориентир из
инструкции агента: в файлах этого репозитория разделы названы по существу
проекта, а не по шаблону.

| Файл | Назначение | Ориентир | Здесь получилось |
|---|---|---|---|
| `llms-full.txt` | самодостаточный контекст проекта | 200–600 строк | 360 строк |
| `llms.txt` | навигационный индекс, без блоков кода | 50–100 строк | 61 строка, блоков кода нет |

### Повторный запуск

Инструкция требует дописать в конец `llms-full.txt` колонтитул с датой и
коммитом, на котором собран файл; в этом репозитории колонтитул стоит. При
следующем запуске агент читает оттуда коммит, берёт `git log HASH..HEAD` и
правит только затронутые разделы. Без колонтитула берёт последние двадцать
коммитов.

### Чего агент не включает

Обучающие материалы, временные обходы, `TODO`/`FIXME`, паттерн из одного файла,
многословные объяснения, очевидные сведения, отладочный вывод, номера строк,
статусы открытых задач, отдельные тест-кейсы, любые секреты. Это список из
инструкции агента.

## Границы

- Файлы рассчитаны на ИИ-инструменты. README для человека плагин не заменяет и
  не пишет.
- Стандарт `llms.txt` описывает файл на сайте — корень домена или путь внутри
  него. Плагин пишет в репозиторий: применение родственное, но не то, о котором
  говорит стандарт.
- Оба пути обновления опираются на `git log`. Поведение в репозитории без git
  инструкция не задаёт.
- Хук смотрит в рабочий каталог процесса: из подкаталога он сообщит о
  подкаталоге.
- Файл — снимок состояния. При расхождении с кодом правдой остаётся код:
  колонтитул `llms-full.txt` отстаёт здесь от `HEAD` на 54 коммита.

## Куда дальше

- Документационную роль в конвейере [planner](planner.md) `/plan-do` берёт из
  таблицы действующих агентов `.claude/planner-context.md`, имя плагина не
  зашито, — занять её может и этот плагин. Договор роли, полный отчёт по
  переданному пути `DOCUMENTATION-NN.md` и сводка в ответ, в инструкции
  `documentation-keeper` не описан: она пишет `llms.txt` и `llms-full.txt`.
- Все виды связей между плагинами — [отдельная страница](relations.md).
