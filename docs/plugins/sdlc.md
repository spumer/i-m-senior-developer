# sdlc

Три агента разработки. Команд и хуков нет — порядок вызова задаёт человек или
`/plan-do` из `planner`.

## Агенты

| Агент | Модель | Делает | Не делает |
|---|---|---|---|
| `architect` | opus | ограниченные контексты, договоры передачи, поток данных, точки интеграции, открытые вопросы | код, тесты, миграции; не запускает тесты |
| `code-implementer` | sonnet | реализует по готовому документу через TDD, запускает весь набор тестов и линтеры | не проектирует, не проводит ревью |
| `code-reviewer` | sonnet | безопасность, принципы ясности, стековые ловушки; замечания со ссылкой `файл:строка` | не правит код, не пишет тесты, не запускает набор тестов |

## Артефакты

```text
<каталог фичи>/ARCHITECTURE.md                    architect
<каталог фичи>/IMPLEMENTATION-NN.md               code-implementer, один файл на реализацию или круг правок
<каталог фичи>/review-request-changes/REVIEW-NN.md  code-reviewer, один файл на раунд
```

Путь архитектурного документа архитектор берёт по порядку: названный
оркестратором (в конвейере planner — из шапки `PLANNER_EXECUTION.md`) →
соглашение проекта из `planner-context.md` → `ARCH-NN.md`.

## Передача между ролями

```text
требования → architect → code-implementer → code-reviewer
```

- Тесты и линтеры запускает `code-implementer` и отчитывается точными командами.
- `code-reviewer` читает диф и этот отчёт; находку, требующую запуска, помечает
  непроверенной.
- Дефект реализации возвращает работу реализующей роли. Замечание к
  проектированию `/plan-do` показывает человеку и останавливает выполнение до
  следующей рабочей фазы. Архитектор сам не вызывается; если человек меняет
  архитектуру, гейт свежести требует пересобрать план выполнения.

При самостоятельном вызове реализатор и ревьюер выводят полный отчёт в чат.
При вызове через `/plan-do` полный отчёт записывается в переданный файл, а в
контекст оркестратора возвращается доказательная сводка. Для реализации и
кругов правок это `IMPLEMENTATION-NN.md`, для ревью —
`review-request-changes/REVIEW-NN.md`.

## Стековые справочники

| Роль | Всегда | По стеку |
|---|---|---|
| `architect` | договоры проектирования | Python, React, дизайн API |
| `code-implementer` | — | Python, React |
| `code-reviewer` | безопасность (OWASP) | Python, React |

Признаки: `*.py` → Python; `*.tsx`, `*.jsx`, `*.ts`, `*.vue`, `*.svelte` →
фронтенд; поверхность API → дизайн API; смешанный стек → оба справочника, сначала
бэкенд; неизвестный стек → универсальные принципы, отказа нет.

Проход по безопасности выполняется всегда и первым; раздел о безопасности
присутствует в отчёте, даже когда находок нет.

## Зависимости

```json
{"dependencies": ["tdd-master", "functional-clarity"]}
```

Ставятся автоматически. Без `tdd-master` цикл тестов допустим общими средствами,
но деградацию нужно отметить в отчёте.

## Ограничения

- Цикл сам не запускается: ни команды, ни хука у плагина нет.
- `architect` требует готовых требований фичи; сырой замысел идёт в `planner`.
- Ревью ставит диагноз, правки делает реализующая роль.
