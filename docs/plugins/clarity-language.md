# clarity-language

Проверка человекочитаемых текстов: три скилла, хук времени записи и workflow
сплошного разбора калек. Находки скиллы возвращают в чат. Записей две:
`russian-style` заносит решение по спорному слову в лексикон проекта, а разбор
калек пишет отчёт файлом.

## Состав

| Скилл | Предмет | Результат |
|---|---|---|
| `clarity-validator` | технические документы: противоречия, спутанные слои, выдуманные процессы, съехавшие термины — 12 паттернов | находки: тип, серьёзность, файл, цитата, диагноз, направление правки |
| `russian-style` | русский текст: кальки, номинализации, пустые антитезы, канцелярит, подставленное панибратство, рассогласование после замены термина | правки формулировок |
| `ai-prose-detector` | художественная проза: 6 методов — дистанция, готовые метафоры, недостоверные детали, переобъяснение, механистичность, монотонность | диагнозы, без готового текста |

Хук `SessionStart` ставит правило времени записи: перечитать человекочитаемый
текст перед каждой записью. Запрещает кальки при наличии родного слова, термины
без пояснения при первом употреблении, внутренние коды в прозе, вычурные образы.

Workflow `clarity-language:calque-sweep` разбирает русские тексты на кальки и
придуманные переводы терминов по правилам `russian-style` — сплошным проходом, а
не по ходу разговора. Итог — файл-отчёт: словарь разобранных слов с вердиктом и
основанием, а следом места будущей замены с фразой целиком, чтобы правку можно
было применить с учётом согласования соседних слов.

## Как пользоваться

### Когда включается какой скилл

Скиллы подключаются сами, каждый по своему предмету запроса.

| Скилл | Запрос, на котором он включается |
|---|---|
| `clarity-validator` | разобрать технический документ: сходятся ли утверждения между собой и между файлами, не съехал ли термин, не описан ли процесс, которого нет |
| `russian-style` | выправить русский текст: вернуть живое слово вместо переводной конструкции, упростить формулировку, проверить окончания у слов рядом с заменённым термином |
| `ai-prose-detector` | вычитать художественный текст, когда он читается машинным |

Точные пусковые формулировки живут в самих скиллах, страница их не повторяет.

### Вызов разбора калек

У workflow нет запускающей команды, и ни один скилл его не вызывает: единственный
вход — его имя, `clarity-language:calque-sweep`. Не зная имени, читатель этот путь
не найдёт, поэтому оно названо здесь.

Область разбора задаётся при вызове: либо перечисленные файлы, либо весь
репозиторий. Умолчания нет — сплошной проход по репозиторию сам собой не
запускается.

### Спорное слово

`russian-style` не решает сам, переводить термин или оставить заимствование:
выносит вопрос человеку, до решения пишет заимствование, принятое решение
записывает в лексикон проекта. Тот же порядок держит и разбор калек — спорные
слова уходят в отчёт отдельным разделом как вопрос человеку, а не как вердикт.

## Границы

- Фактическую правду текста ни один из трёх скиллов не проверяет.
- `clarity-validator` без списка файлов не угадывает область — спрашивает.
- `ai-prose-detector` настроен на психологический триллер и киберпанк, другие
  жанры требуют адаптации критериев; авторство «человек или ИИ» не определяет.
- Разбор калек текста не правит: замены он только предлагает, применяет их
  человек.
