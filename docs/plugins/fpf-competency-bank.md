# fpf-competency-bank: эталонный банк сводов

## Что это

Плагин без команд, скиллов, агентов и хуков. Только данные: два проверенных
свода компетенций и карта, по которой их находит резолвер.

- **`DPF-COUPLING-GENERALIZATION`** — доменный свод о том, когда более крупная
  правка сокращает связи между объектами, а когда только кажется, что сокращает.
- **`LPF-SIMPLIFICATION-REVIEW`** — локальная практика ревью-обобщения дифов на
  стадии упрощения; заодно образец того, как выглядит свод этого класса.
- **карта компетенций** — идентификаторы, пути, вид, статус, редакция, режимы и
  ключевые слова.

Ключевые слова карты читает хук из [fpf-integration](fpf-integration.md) — сам
банк ничего не запускает и никуда не пишет.

## Для чего это

Чтобы у резолвера был проверенный набор для начала работы, а у авторов сводов —
образец, на который можно посмотреть вместо чтения спецификации. В банк
попадает только то, что прошло оба слоя допуска: свод со статусом заготовки или
требующий ремонта не входит, как бы аккуратно он ни был оформлен.

## Как пользоваться

```text
/plugin install fpf-competency-bank@i-m-senior-developer
```

Установка подтянет `fpf-integration` — без резолвера банк бесполезен. Дальше
подключение делается вручную и осознанно: абсолютный путь к каталогу сводов
банка дописывается в `~/.claude/frameworks.paths`. Автоматической записи в этот
файл при установке нет.

После подключения своды видны резолверу наравне с проектными и
пользовательскими.

## Когда НЕ пользоваться

- **Как готовая практика для чужого проекта.** Локальный свод нельзя применять
  как есть: его нужно форкнуть, адаптировать под свой контекст и читателя и
  заново прогнать проверку. Унаследованный вердикт допуска на новый контекст не
  переносится.
- **Без резолвера.** Банк — данные. Исполнять их умеет только
  [fpf-integration](fpf-integration.md).
- **Как хранилище своих сводов.** Проектные своды живут в проекте; банк —
  эталонный набор с собственными правилами допуска.
