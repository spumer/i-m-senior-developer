# fpf-integration: первопринципы и своды компетенций

## Что это

Самый крупный плагин витрины: четыре скилла, агент-гейт и два хука.

| Компонент | Что делает |
|---|---|
| скилл `fpf-integration` | внедрение первопринципов в проект: аудит решений, граф подтверждений, проверка альтернатив, механизм устаревания решений, чеклисты ролей |
| скилл `dpf-authoring` | шестифазный конвейер создания, доавторинга, переоценки и ремонта свода |
| скилл `dpf-apply` | резолвер и исполнитель сводов: находит свод по уровням проект → пользователь → плагин, проверяет свежесть, работает в режиме подготовки или применения, ведёт журнал применений |
| скилл `end-session-setup` | ставит в проект ритуал закрытия сессии с записью применений |
| агент `dpf-gate` | проверяет допуск свода до начала работы, называет режим и возвращает план; инструментов записи у него нет |
| хук на старт сессии | печатает карту доступных сводов по уровням, помечает протухшие; при пустом наборе молчит |
| хук на входящий запрос | даёт до трёх подсказок по точному идентификатору свода или ключевым словам карты; сам ничего не применяет и запрос не блокирует |

Разделение резолвера и данных — принципиальное: сам плагин не содержит ни одной
компетенции. Своды приходят из проекта, из пользовательского каталога или из
плагина-банка.

## Для чего это

Чтобы решения имели носителя. Утверждение без цепочки подтверждений — это
мнение, а мнение нельзя ни проверить, ни оспорить по существу. Плагин делает
подтверждения обязательной частью решения, а устаревание — явным событием, а не
молчаливым дрейфом.

Второе — повторное применение компетенции. Свод описывает, как эта команда
решает определённый класс задач; резолвер применяет его одинаково, а журнал
хранит, где он уже применялся и с каким результатом.

## Как пользоваться

Точка входа — агент-гейт, до самой работы: он проверяет допуск, свежесть и
совпадение редакции, называет режим и возвращает план на подтверждение.

Дальше — обычными репликами: «примени компетенцию», идентификатор вида
`DPF-*`/`LPF-*`, «создай DPF», «переоцени свод», «поставь end-session», «добавь
FPF в проект», «проверь качество подтверждений».

Что появляется на диске: своды в каталоге сводов проекта, отчёт переоценки
рядом со сводом, журнал применений внутри пакета, команда закрытия сессии в
`.claude/commands/`, а для репозитория с кодом — раздел в правилах проекта.

## Когда НЕ пользоваться

- **Нет источника справочника.** Скилл требует справочник первопринципов через
  MCP или локальную копию. Без источника он останавливается и просит настроить
  источник, а не работает вслепую и не переходит в облегчённый режим.
- **Опечатка или одна строка в своде.** Шестифазный конвейер для этого не
  запускается: предписана точечная правка.
- **Применение свода «просто так».** Нужна пара «свод × заявленное применение».
  Без этого применение не начинается.
- **Ожидание, что гейт сделает работу.** Он возвращает план и отказ; читать свод
  в контекст, запускать конвейер и править файлы — не его полномочия. Для задачи
  не о сводах он просто возвращает управление.
- **Копирование текста свода в промпты.** Прямо запрещено: свод применяется
  резолвером, а не вставкой.
- **Протухший свод.** Отказ по свежести или конфликту редакции — это результат
  работы гейта, а не помеха: он означает, что свод нужно переоценить.
