# tdd-master

Цикл красный–зелёный–рефакторинг: скилл, агент и хук на старт сессии.

## Состав

| Компонент | Что делает |
|---|---|
| хук `SessionStart` | вносит в сессию правило: реализация только после падающего теста |
| скилл `tdd-master` | методология, выбор справочников по стеку |
| агент `tdd-master` | пишет тесты; поведение зависит от способа вызова |

## Два режима агента

| Вызов | Что делает |
|---|---|
| напрямую | весь цикл: падающий тест → минимальная реализация → рефакторинг |
| из другого агента | останавливается после красной фазы: создаёт файл тестов, возвращает список тестов; зелёную фазу делает вызывающая роль |

## Триггеры скилла

«write tests», «add tests», «fix bug», «TDD», «write failing test»,
«Red-Green-Refactor», а также запрос на реализацию новой функциональности.

## Определение стека

| Найдено | Справочник |
|---|---|
| `pyproject.toml`, `conftest.py` | pytest |
| `manage.py` | Django |
| ничего из перечисленного | общий справочник по TDD |

## Запреты

- реализация без падающего теста;
- пропуск рефакторинга;
- тесты, которые проходят всегда;
- `raise Exception` вместо `pytest.fail()`;
- заглушки вместо своей бизнес-логики — только вместо внешних сервисов.

## Ограничения

- Правка текста или промпта без наблюдаемого контракта тестом не покрывается:
  придумывать проверку ради красной фазы запрещено правилами проекта.
- В делегированном режиме агент реализацию не пишет.
