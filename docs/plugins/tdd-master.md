# tdd-master

Помогает писать код через проверяемое поведение: сначала падающий тест, затем
минимальная реализация и рефакторинг.

## Основные возможности

- Фиксирует ожидаемое поведение тестом до реализации, чтобы проверка не
  подгонялась под готовый код.
- Помогает убедиться, что тест падает по нужной причине, а не из-за случайной
  ошибки.
- Ведёт от минимального решения к рефакторингу, снижая риск преждевременного
  усложнения.
- Даёт готовые приёмы для pytest и Django: фикстуры, параметризацию, моки
  внешних сервисов и проверку побочных эффектов.

## Состав

Метод «красный–зелёный–рефакторинг»: реализация начинается после падающего
теста. Плагин поставляет текст этого метода — скилл, агента и хук, который
печатает правило при старте сессии. Порядок фаз держится этими указаниями.

| Компонент | Предметная роль |
|---|---|
| хук `SessionStart` | печатает при старте сессии указание: реализацию без падающего теста не писать |
| скилл `tdd-master` | метод: порядок фаз, запреты, выбор справочника по стеку |
| агент `tdd-master` | отдельная роль с тем же методом: пишет тесты и ведёт цикл |

Команд плагин не поставляет: цикл включает скилл или вызывающая роль.

## Как пользоваться

### Когда включается скилл

Скилл объявлен так, чтобы включаться без явного вызова, когда в запросе речь о
написании или добавлении тестов, о воспроизведении бага падающим тестом или о
реализации новой функциональности. Пусковые формулировки живут в описании
скилла, страница их не повторяет.

### Цикл и агент

Пять шагов: список сценариев, падающий тест, минимальная реализация,
рефакторинг, повтор со следующим сценарием. Перед прогоном теста скилл велит
предсказать, чем именно тест упадёт, и сверить предсказание с фактическим
падением.

Текст агента описывает и весь цикл целиком, и отдельный порядок по вызову из
другой роли: создать файл тестов, вернуть список, дать вызывающей роли написать
реализацию, затем убедиться, что тесты проходят. Что из двух произойдёт, решает
модель по контексту вызова — развилки в тексте нет.

### Справочник по стеку

Скилл велит перед написанием тестов определить стек по файлам зависимостей
(`pyproject.toml`, `requirements.txt`, `setup.cfg`, `Pipfile`), по конфигурации
(`conftest.py`, `pytest.ini`, `manage.py`, `settings.py`) и по импортам и
маркерам в существующих тестах. Справочников четыре; точка входа —
`plugins/tdd-master/skills/tdd-master/SKILL.md`, сами файлы лежат рядом с ним:

| Справочник | Когда читать | О чём |
|---|---|---|
| `references/TDD_GUIDE.md` | всегда | свод цикла: три закона, принципы FIRST, анти-паттерны, изоляция и моки, TDD с ИИ-агентами |
| `references/P0_DEFAULT_CONTEXT.md` | всегда | значения по умолчанию по роли объекта: FK — минимум, точка входа — максимум, edge case — явное отклонение |
| `references/frameworks/pytest.md` | обнаружен pytest | фикстуры, параметризация, помощники сравнения, моки внешних сервисов, контроль времени, проверка логов |
| `references/frameworks/django.md` | обнаружен Django | `django_db`, factory_boy, фоновые задачи, состояние моделей, сигналы, события ESB, часовые пояса |

Общие справочники читаются вместе с фреймворочным, а не вместо него: при pytest
и Django одновременно скилл предписывает прочитать все четыре. Полный текст
правил остаётся в справочниках, страница называет только их назначение.

### Что цикл запрещает

Запреты живут списком критических правил в скилле и в агенте:

- реализация без падающего теста;
- пропуск рефакторинга;
- тесты, которые проходят всегда;
- `raise Exception` вместо `pytest.fail()`;
- заглушки вместо своей бизнес-логики — только вместо внешних сервисов.

## Границы

- Цикл сам не запускается: команд у плагина нет, а хук печатает текст один раз
  при старте сессии, до вызовов инструментов, и записи файла не видит.
- Агент не ограничен в инструментах: продуктовый код он может писать и в том
  порядке, который отводит реализацию вызывающей роли.
- Готовые образцы — только Python: фреймворочные справочники и примеры написаны
  под pytest и Django, сам свод цикла от языка не зависит.
- Правка текста и промпта: запрет «нет падающего теста — нет кода» сформулирован
  без исключений. Оговорку для документации и смысла промпта задаёт `AGENTS.md`
  этого репозитория.
