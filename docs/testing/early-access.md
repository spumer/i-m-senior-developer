# Ранний доступ к `claude plugin eval`

Команда собрана во всех текущих сборках и полностью объявлена в справке, но
запуск разрешается по организации. При закрытом гейте команда печатает одну
строку и выходит с кодом `1`:

```text
`plugin eval` is currently in early access
```

Публичной страницы документации у команды пока нет.

## Самопроверка

Проверять нужно в пустом каталоге, а не в репозитории с кейсами:

```bash
tmpdir=$(mktemp -d)
(cd "$tmpdir" && claude plugin eval)
```

- `currently in early access` — разрешение до процесса не дошло;
- `No eval cases found` — гейт открыт.

Код выхода в обоих случаях `1`, различать состояния нужно по тексту.

## Как открывается гейт

Разрешение включается на стороне организации и приходит клиенту вместе с
фича-флагами. Первичные клиенты подхватывают его после `claude update` и новой
сессии.

Клиент со своим `ANTHROPIC_BASE_URL`, трафиком через шлюз или выключенной
неосновной телеметрией эти флаги не получает никогда. В CLI `2.1.234` проверка
выглядит так:

```text
серверный флаг tengu_walnut_spire ИЛИ CLAUDE_CODE_WALNUT_SPIRE
```

Поэтому в этом репозитории оценка включена переменной:

```json
{
  "env": {
    "CLAUDE_CODE_WALNUT_SPIRE": "1"
  }
}
```

Место — пользовательский `~/.claude/settings.json`, окружение оболочки или
управляемые настройки.

## Куда переменную класть нельзя

Проектный `.claude/settings.json` для этого не годится. До подтверждения доверия
к рабочей области из проектных настроек применяется только белый список
переменных, и этой в нём нет: закоммиченное значение оставит команду закрытой.

Имя переменной внутреннее и может измениться при обновлении CLI. После каждого
обновления повторяйте самопроверку.
