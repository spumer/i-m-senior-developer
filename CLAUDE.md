# i-m-senior-developer — Plugin Marketplace

Монорепозиторий плагинов для Claude Code. Распространяется через GitHub.

## Версионирование плагинов

Версия плагина в `.claude-plugin/plugin.json` считается **относительно последнего релиза (тега `vX.Y.Z`), а не относительно предыдущего изменения**. Бамп делается **один раз — при выпуске**, отражая суммарный характер изменений плагина с последнего релиза (наибольший применимый шаг semver). Внутри невыпущенного окна версию на каждый коммит не поднимают: Claude Code кеширует по версии только у **выпущенных** плагинов, поэтому промежуточные бампы ничего не дают и лишь копятся.

Плагин, созданный после последнего тега, ещё не выпускался — правки в него до релиза версию не бампают (он весь — один будущий первый выпуск).

Как считать шаг (**Semantic Versioning**, semver.org) — относительно версии плагина в последнем теге:
- **MAJOR** (1.0.0 → 2.0.0) — breaking changes: удалены/переименованы команды, агенты, изменён формат
- **MINOR** (0.1.0 → 0.2.0) — новая функциональность: добавлены команды, агенты, скиллы
- **PATCH** (0.1.0 → 0.1.1) — исправления: баги, опечатки, уточнения в промптах

## Релизный workflow

1. Внести изменения в плагин(ы) — коммитами по мере работы, **без бампа версии в каждом**
2. При выпуске — бампнуть `version` каждого затронутого плагина **относительно его версии в последнем теге** (один шаг semver на весь набор изменений с релиза)
3. Коммит + тег: `git tag vX.Y.Z`
4. Push: `git push && git push --tags`
