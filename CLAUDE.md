## Сообщения коммитов

Заголовок не начинается с инфинитива: «добавить», «согласовать», «проверять» —
это калька с английского императива, по-русски так не пишут. Заголовок — законченное
утверждение о результате: «Договоры передачи между ролями согласованы», «Добавлен
хук продуктового входа».

Префикс по типу изменения и область сохраняются: `fix(planner,sdlc): …`,
`docs: …`. Тело объясняет причину — почему так, а не перечисление файлов, которые
и так видны в диффе.

## Документация

Сайт документации собирается Zensical из `docs/` и публикуется в GitHub Pages
workflow `docs.yml` при пуше в `master`. Разделение содержания обязательно:

- `docs/plugins/` — что даёт каждый плагин и как плагины связаны между собой;
- `docs/testing/` — общие правила проверки плагинов, одинаковые для всех;
- `docs/reports/` — отчёты по конкретным плагинам, по одному файлу на плагин.

Отчёт описывает наблюдённый прогон, а не замысел проверки. Пилотный запуск с
одним повтором успехом не записывается.

Локальная сборка: `zensical build`. Каталог `site/` не коммитится.

## Зависимости плагинов

Межплагинные зависимости объявляются полем `dependencies` в манифесте плагина и
только когда без второго плагина договор первого неполон. Объявленные сейчас:
`sdlc` → `tdd-master`, `functional-clarity`; `fpf-competency-bank` →
`fpf-integration`.

Ограничения версий не добавлять, пока релизы плагинов не тегируются отдельно как
`{плагин}--v{версия}` через `claude plugin tag`: общий тег `vX.Y.Z` для них не
резолвится. Разбор видов связи — в `docs/plugins/relations.md`.
